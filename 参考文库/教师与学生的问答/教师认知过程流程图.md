## 二、一次提问的完整流程

```
学生: "行列式展开定理中，等式为什么能成立？" (第71页, V1-C02-S04)
│
├─ 1. Domain Model 查询 (并行)
│   ├─ Neo4j: 当前章节Section → TEACH_IN → 30个概念 → 白名单 ✅
│   ├─ Neo4j: PREREQUISITE_OF*2 → 60个前置概念
│   └─ textbook_sections: 第68-84页MD原文
│
├─ 2. Learner Model 查询 (并行)
│   ├─ 对60个前置概念: get_batch_mastery() → 每个概念的 P(mastered) + stage
│   │   ┌──────────┬──────────┬────────┬───────────┐
│   │   │ 概念      │ P(master)│ stage  │ 状态      │
│   │   ├──────────┼──────────┼────────┼───────────┤
│   │   │ 余子式    │ 0.75     │ 3      │ 基本掌握   │
│   │   │ 子式      │ 0.60     │ 2      │ 学习中     │
│   │   │ 排列      │ 0.30     │ 1      │ ⚠ 薄弱    │
│   │   │ 逆序数    │ 0.20     │ 0      │ ❌ 未掌握  │
│   │   │ 提取公因子 │ 0.85     │ 4      │ 熟练      │
│   │   └──────────┴──────────┴────────┴───────────┘
│   └─ 15维画像: so_technical=1 (符号操作偏弱)
│
├─ 3. 诊断引擎 (交叉判断)
│   ├─ 意图解码: "等式为什么成立" = 在追问逻辑链条, 不是符号问题
│   ├─ 前置追溯: 逆序数(0.20) 和 排列(0.30) 是薄弱点
│   │   但"提取公因子"(0.85) 熟练 → 他不是代数基础的问题
│   ├─ ZPD 定位: 当前在 stage=2 (行列式展开), 
│   │   前置链断裂点在"排列→逆序数"
│   └─ 深度校准: 不需要从头讲, 给一个3阶具体例子引导即可
│
│   → 诊断结果: {
│       intent: "逻辑链条追问",
│       weak_links: ["逆序数", "排列"],
│       zpd_target: "行列式展开的符号变换",
│       depth: "light_hint"  // 不需要降级重讲
│     }
│
├─ 4. 策略引擎 (选择+生成)
│   ├─ 策略选择: "简化" (给3阶例子) + "提问" (让他自己推n阶)
│   ├─ 回答生成: LLM(
│   │     role = "你是一个数学导学教练",
│   │     strategy = "先给一个3阶的具体例子, 然后让学生类推到n阶",
│   │     weak_aware = "学生逆序数薄弱, 如果回答涉及符号(-1)^{i+j}要额外解释",
│   │     textbook_context = "行列式按一行展开, 第68-84页...",
│   │     question = "等式为什么能成立"
│   │   )
│   └─ → AI回答: "我们看一个3阶的例子。写出|A|的6项展开式, 
│       然后按第一行元素分组提取公因子。你试试看？"
│       (没有直接讲逆序数——因为深度校准判断不需要)
│
├─ 5. Learner Model 更新 (实时)
│   ├─ 逆序数: ask_count += 1 (又被间接提及)
│   ├─ 行列式展开: ask_count += 1
│   └─ 如果学生追问 → 可能触发重新评估
│
└─ 6. 反馈面板更新 (独立于聊天)
    └─ OLM显示: "行列式展开"旁边出现一个绿点(正在学习)
```

## 五、改造路线图

### Phase 1: 让 Learner Model 活起来

#### 为什么改

当前的 `knowledge_stages` 表是空的。kz 用户使用了几个月的系统，表里 0 条记录。这导致：

- `get_prereq_gaps()` 查到 299 个前置概念，全部标记为 gap
- `get_stage()` 永远返回 NULL → `scaffolding_controller` 永远用默认值 MODELING
- 前置提醒块是随机从 299 个概念中取前 8 个，其中包含脏数据（"(1)"、"不同时"）
- **整个 Adaptive Model 的运行基础不存在**

具体问题链路：

```
init_concepts_for_section() 从未被调用
  → knowledge_stages 空表
    → prerequisite_checker 的前置检测全无效
    → scaffolding_controller 的学徒层级无意义
    → prompt_engine 的前置提醒块是瞎编的
    → AI 无法根据学生真实掌握情况调整回答
```

#### 改什么

**改法 1：补调用 `init_concepts_for_section()`**（不是真需求）

[qa.py:197-207](app/routers/qa.py#L197-L207) 已 import 但从未调用。每次学生进入新章节时，需要先初始化该章节的概念记录。

当前代码：
```python
try:
    from app.services.prerequisite_checker import get_prereq_gaps
    from app.db.knowledge_stages_db import get_stage, init_concepts_for_section
    
    prereq_gaps = get_prereq_gaps(sequence_id, user_id)
    # ... init_concepts_for_section 从未被调用
except Exception:
    pass
```

修复后：
```python
try:
    from app.services.prerequisite_checker import get_prereq_gaps
    from app.db.knowledge_stages_db import get_stage, init_concepts_for_section
    
    # 首次进入章节 → 初始化概念列表
    concepts = get_concepts_by_sequence_id(sequence_id)  # Neo4j 已有
    if concepts:
        init_concepts_for_section(user_id, concepts)
    
    prereq_gaps = get_prereq_gaps(sequence_id, user_id)
except Exception:
    pass
```

**改法 2：每次问答后实时更新 Learner Model**（有严重大问题！！）

不再设 24h 锁。每次 LLM 回答后，在后台异步更新：

```python
# qa.py: LLM 回答完成后
background_tasks.add_task(
    update_learner_model,
    user_id=user_id,
    topic=chapter_name,
    question=question,
    concepts_involved=concepts_from_whitelist,
    prereq_gaps=prereq_gaps,
)
```

更新逻辑（非侵入，不阻塞用户）：
```
对每个涉及的概念：
  问了一次 → ask_count += 1
  学生追问了同一概念 → consecutive_asks += 1, P += 0.05
  学生过了很久又回来问 → 可能遗忘了, P -= 0.05
  学生在练习中答对了 → P += 0.15, stage = max(stage, 3)
```

**改法 3：诊断触发的粒度从"章节级别"细化到"概念级别"**（不切实际！）

当前触发条件是 `consecutive_turns`（同一 topic 连续问 3 次）。改为按概念粒度：

```
某个 Concept 的 ask_count >= 3 AND 最近一次问答距今 < 7 天
  → 对这个 Concept 触发一次轻量评估（不是完整的 15 维诊断）
  → 更新这个 Concept 的 stage 和 P(mastered)
```

#### 怎么改

涉及文件：

| 文件 | 改动 |
|------|------|
| `qa.py` line 197-207 | 补调用 `init_concepts_for_section()` |
| `qa.py` line 265-287 | 加`update_learner_model` 后台任务 |
| 新建 `app/services/learner_model_updater.py` | Per-concept 更新逻辑 |

| `knowledge_stages_db.py` | 添加 `batch_init`、`batch_update` 等方法 |

预期效果：
- 第一次提问后，`knowledge_stages` 表就有数据
- 第二次提问后，前置检测开始有意义
- 第三次提问后，scaffolding 层级开始根据真实数据变化
- 第七天后，学生的知识地图开始成形

### Phase 2: 拆分诊断引擎和策略引擎

#### 为什么改

当前 [prompt_engine.py](app/services/prompt_engine.py) 的 `build_prompt()` 做了一件很粗暴的事：把 10 路信号拼成一段自然语言文本，然后期待 LLM 在这段文本里同时完成 **诊断**（学生哪里弱？）**决策**（该怎么教？）**生成**（具体说什么？）三项任务。

这在教育文献里被称为 **"end-to-end black box prompting"**。Wang et al. (2024, NAACL) 的实验证明：LLM 在没有结构化决策辅助的情况下，倾向于走同质化路径——总是直接解释，极少提问或引导。Merrill et al. (1992) 在 30 年前就发现：好教师的关键是策略多样性。

具体问题：
- LLM 的诊断是不可见的——你不知道它怎么判断学生状态的
- LLM 的策略选择不可控——每次回答的策略全凭 LLM 自己决定
- 无法迭代改进——改诊断还是改策略？不知道，因为混在一起
- ChatBack (Liang et al., 2023) 证明：诊断反馈应该独立于对话内容

#### 改什么

**将 prompt_engine 拆为三层**：

```
当前：
  prompt_engine.build_prompt(10个信号) → 一段文本 → LLM → 回答

改后：
  诊断引擎(结构化输入) → 诊断结果(JSON) → 策略引擎(规则+Learner Model) → 策略+约束 → LLM → 回答
```

**第一层：诊断引擎 → 产出结构化 JSON**

```python
# app/services/diagnosis_engine.py
def diagnose(question, page_context, whitelist, learner_model, prereq_gaps):
    """
    不是让 LLM 自由发挥，而是基于结构化数据做规则判断。
    LLM 只用于"意图解码"这一个人工智能擅长的子任务。
    """
    return {
        "intent": classify_intent(question),           # 规则: 关键词匹配 + LLM分类
        "zpd_level": compute_zpd(learner_model),        # 规则: 前置链上最弱的一环
        "weak_links": get_weakest_prereqs(prereq_gaps), # 数据: 从 learner_model 查询
        "depth": calibrate_depth(question, learner_model), # 规则: 难度+学生水平的匹配
        "confidence": compute_confidence(learner_model)  # 数据: 模型不确定性
    }
```

意图分类（`classify_intent`）——基于专家教师的五类判断：

| 意图类别 | 典型措辞 | 对应策略 |
|---------|---------|---------|
| 概念理解 | "XX 是什么意思" | 类比/简化 |
| 逻辑追问 | "为什么能成立" | 引导提问 |
| 符号操作 | "这个变换怎么做" | 分步示范 |
| 综合应用 | "这题怎么解" | 提示 + 让学生试 |
| 确认检查 | "对吗？是这样吗" | 简短确认 + 追问 |

**第二层：策略引擎 → 从策略库选择，生成 LLM 约束**

```python
# app/services/strategy_engine.py
STRATEGY_LIBRARY = {
    ("概念理解", "MODELING"):   ("类比", "用一个生活中的例子引入"),
    ("概念理解", "COACHING"):   ("简化", "用最简单的特例展示"),
    ("概念理解", "SCAFFOLDING"): ("提示", "给定义的关键词，让学生自己说"),
    ("逻辑追问", "MODELING"):   ("示范", "展示完整的逻辑推导过程"),
    ("逻辑追问", "COACHING"):   ("提问", "引导式提问，一步步让学生推"),
    ("逻辑追问", "SCAFFOLDING"): ("提示", "指出推理链条上哪一步有问题"),
    ("符号操作", "MODELING"):   ("示范", "完整写出每一步变换"),
    ("符号操作", "COACHING"):   ("简化", "先用数字例子，再推广到符号"),
    # ... 5意图 × 4学徒层级 = 20种组合
}

def select_strategy(intent, apprenticeship_level, learner_model):
    key = (intent, apprenticeship_level)
    strategy_name, strategy_guidance = STRATEGY_LIBRARY.get(
        key, ("解释", "用清晰的结构讲解")
    )
    
    # 加入 Learner Model 的约束
    constraints = {
        "avoid_concepts": get_prereq_gaps_for_answer(learner_model),
        "weak_aware": format_weak_points_for_llm(learner_model),
        "textbook_ref": get_relevant_pages(),
    }
    
    return strategy_name, strategy_guidance, constraints
```

**第三层：LLM → 只回答问题**

LLM 的输入不再是一段混杂的 System Prompt，而是结构化的指令：

```
System: 你是一位数学导学教练。
Strategy: 类比引导。用一个生活中的例子引入行列式展开的概念。
Constraints:
  - 不要直接给出定义（学生处于 MODELING 阶段）
  - 避免使用逆序数、排列这两个概念（学生未掌握）
  - 教材参考：行列式展开在70-84页
  - 回答控制在 200 字以内，以一个问题结尾
Question: 行列式展开定理怎么理解？
```

#### 怎么改

涉及文件：

### Phase 3: 前端重构——Open Learner Model

#### 为什么改

Bull & Kay (2007) 的元分析表明：把学生模型可视化后，学生的元认知能力、自主性和学习动机都显著提升。ChatBack (Liang et al., 2023) 证明：诊断反馈放在独立 GUI 面板的效果远优于嵌入聊天对话。Bloom (1984) 列举的关键变量之一是"学生主动参与和对自己学习状态的认知"。

当前 ProfilePanel 的问题：
- 只是一个统计面板（雷达图+轨迹），不是 Open Learner Model
- 没有知识地图——学生看不到"我和课本知识图谱的关系"
- 诊断结果嵌在 System Prompt 里，学生完全看不到
- 学生不知道 AI 为什么这样回答，也不知道自己该学什么

#### 改什么

**改法 1：对话面板保持纯粹**

ChatPanel 只做一件事：学生和 AI 的问答。不嵌入诊断信息，不嵌入学习建议。

**改法 2：新建 OLM 仪表盘**

替代当前的 ProfilePanel，包含三个视图：

```
┌─────────────────────────────────────────────┐
│  📊 学习仪表盘                               │
├─────────────────────────────────────────────┤
│                                             │
│  ┌─ 知识地图 ──────────────────────────┐    │
│  │  以 Neo4j 子图可视化当前章节的前置链:  │    │

│                                             │
│  ┌─ AI 诊断面板 ───────────────────────┐    │
```

**改法 3：练习面板改为引导式纠错**

基于 ChatBack 的发现，出题/批改功能的反馈改为：
1. 学生提交答案
2. 系统不直接显示正确答案
3. 先给元认知提示（"这一步的符号好像有问题，检查一下？"）
4. 学生修改一次后还不对 → 给更具体的提示（"问题出在逆序数的计算上"）
5. 第三次还不对 → 给出完整解答
