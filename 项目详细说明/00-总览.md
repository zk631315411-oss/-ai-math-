# 00 — 架构总览

## 当前定位

项目当前对外名称建议为 **学数有道**，定位为“基于学科知识图谱的大学数学认知诊断与个性化导学智能体”。原有架构中的问答、画像、知识图谱、智能出题和对话管理，不再只服务“高等代数智能问答”，而是共同形成认知诊断闭环：根据学生真实学习过程判断其为什么不会，并给出可解释、可追踪、可验证的个性化干预。

详细竞赛定位见 [09-竞赛定位与认知诊断闭环](09-竞赛定位与认知诊断闭环.md)。

## 板块依赖关系

```
09-竞赛定位与认知诊断闭环
                   │
06-用户认证 ──→ 01-智能问答 ──→ 07-对话管理
                   │
                   ├──→ 02-学生画像 ←── 03-知识图谱
                   │        │
                   ├──→ 04-智能出题
                   │
                   ├──→ 05-教材系统
                   │
                   └──→ 08-截图交互
```

**核心链路**：认证（06）是入口 → 问答（01）是主流程 → 对话管理（07）沉淀学习证据 → 画像（02）+ 图谱（03）形成认知诊断大脑 → 出题（04）输出补救练习。教材（05）和截图（08）是输入通道，竞赛定位（09）定义这些模块共同服务的产品主线。

## 数据库表概览

| 表 | 用途 | 主要读写 |
|----|------|---------|
| `users` | 用户账户 | 注册/登录时写入 |
| `math_profiles` | 15 维素养分数 + 诊断报告 | 诊断管线写入，问答时读取 |
| `knowledge_stages` | 每个概念的认知阶段 0-5 | 诊断/练习写入，脚手架读取 |
| `pending_stage_updates` | stage 更新队列 | pending_worker 消费 |
| `question_assessments` | 诊断快照历史 | 诊断管线写入 |
| `chat_logs` | 后端对话日志（诊断语料） | qa.py 写入，diagnostic_worker 消费 |
| `chat_history` | 前端对话历史（展示用） | 前端写入，诊断读取 |
| `user_knowledge_stats` | 知识点提问统计 | qa.py 更新，诊断触发判断 |
| `user_profiles` | 用户基础画像 | 手动编辑 |
| `exercise_bank` | 习题库 | 出题时查询 |
| `exercise_records` | 答题记录 | 练习提交时写入 |
| `textbook_sections` | 教材章节页码映射 | 问答时查询 |
| `textbook_progress` | 教材学习进度 | 页面标记时更新 |
