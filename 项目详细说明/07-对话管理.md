# 07 — 对话管理

对话管理模块负责存储、查询和管理学生与 AI 的对话历史。

在“学数有道”的新定位下，对话历史不是普通聊天记录，而是认知诊断的数据证据。每一轮提问、追问、提示请求、学生修正和 AI 干预，都可能用于判断学生当前掌握了什么、卡在哪里、是否依赖提示。

## 三存储层

| 表 | 角色 | 用途 |
|----|------|------|
| `qa_turn_records` | 主表 | QA 事实记录（完整 context_snapshot / messages_snapshot），异步持久化，V2 诊断消费 |
| `chat_history` | 前端展示 | 对话历史 + 页面标记（marker_type / marker_y_ratio / thumbnail / crop_bbox），前端读写 |
| `chat_logs` | 兼容写 | 后端对话日志（兼容旧诊断），`is_analyzed` 字段保留但**不再作为诊断触发源** |

### qa_turn_records（主表）

`turn_store.save_turn_record()` 由 StreamBus 的持久化消费者异步写入（不阻塞 SSE 响应）：

```
QA 回答完成 → bus.emit(done)
  └─ 持久化消费者（start_persist_consumer）→ save_turn_record()
       ├─ qa_turn_records（主表：完整结构化上下文）
       ├─ chat_logs（兼容写，save_chat_log）
       └─ chat_history（前端已创建 chat_id 时，补 answer / thinking / screenshot_context_id）
```

### chat_history（前端表）

前端在提问前创建记录（answer 初始为空），SSE 结束后由 `turn_store` 异步调用 `update_chat_answer` 补全：

```
前端 POST /api/chat/history  → 创建记录（answer=""，含标记字段）
  ↓
后端 SSE 流式返回完成
  ↓
异步 update_chat_answer(chat_id, answer, thinking, follow_ups)
```

### chat_logs（兼容写）

后端在每次问答完成后兼容写入，含 `is_analyzed` 字段；该字段是旧诊断 worker 的遗留标记，**V2 不再以它为诊断触发源**（V2 直接消费 `qa_turn_records` 与 `exercise_attempts`）。

## 对话树（chat_trees / chat_nodes / chat_messages）

2026-08-02 引入规范化树形对话存储（[chat_tree_db.py](../app/db/chat_tree_db.py)）：

| 表 | 用途 |
|----|------|
| `chat_trees` | 对话树根（root_chat_history_id / last_active_node_id / revision） |
| `chat_nodes` | 树节点（parent_node_id / fork_message_id / archived_at / version_group_id） |
| `chat_messages` | 节点内消息（role / sequence_no / turn_id，按序追加） |

- 旧 `chat_history.follow_ups` 保留为兼容格式，树是规范化表示；
- 树对话由路由层识别（`client_turn_id` + `node_id`），QA 每轮通过 `begin_turn` / `finish_turn` 写持久化回合；
- 分支（fork）、节点引用（chat_node_references）、归档/恢复、学习摘要树（summary_trees / summary_nodes）均以事务方式操作；端点清单见 [00-总览](00-总览.md) 中的 chat_tree.py 汇总。

## 对话截断策略

| 位置 | 截断规则 | 说明 |
|------|---------|------|
| 文本路径 Prompt（lightweight） | 最近 **3 轮**（`history[-3:]`，prompt_builder.py L192） | 默认工具链路；去教材全文，LLM 可调 search_textbook |
| 视觉路径 Prompt（vision） | 最近 **6 轮**，user ≤ 300 字、asst ≤ 2000 字（prompt_builder.py L390-396） | 截图直接回答路径 |
| V2 诊断评分器 | 最近三轮（adapters.py L177）+ 引文自检 | 引文必须是学生原文/学生答案的精确子串（scorers.py L68-71），不可靠时 not_observed / 弃权 |
| 日志显示 | 全文存储 | 用于前端回看 |

## 诊断证据字段（已实现）

`diagnostic_evidence` 证据账本已落地以下结构化字段：

| 字段 | 用途 |
|------|------|
| `student_quote` | 支持诊断判断的学生原文精确子串（引文自检通过） |
| `behavior` | 行为类型（question_only / self_report / definition_recall / solution_attempt / explanation / proof / counterexample / transfer） |
| `observation_type` | stage（概念观察）或 dimension（素养观察） |
| `strength` | certain / probable / hypothesis（只影响投影权重，不直接改画像） |

这些字段与 KG 的 `evidence_span`（教材原文片段）一起构成诊断卡片的"判断依据"，避免诊断看起来像模型臆测（见 [02-学生画像](02-学生画像.md) 与 [10-KG资产与认知诊断推理](10-KG资产与认知诊断推理.md)）。

## API 端点

[chat.py](../app/routers/chat.py) 5 个端点：

| 端点 | 用途 |
|------|------|
| `GET /api/chat/history/{user_id}` | 获取对话历史（含页码标记，limit / page / id 过滤） |
| `POST /api/chat/history` | 保存对话/标记（answer 可为空，截图/文字提问时调用） |
| `PATCH /api/chat/history/{chat_id}` | SSE 完成后更新：answer / thinking / follow_ups（一个请求） |
| `DELETE /api/chat/history/{chat_id}` | 删除对话 |
| `POST /api/chat/migrate` | 匿名→登录标记迁移 |
