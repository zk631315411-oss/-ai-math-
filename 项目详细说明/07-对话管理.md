# 07 — 对话管理

对话管理模块负责存储、查询和管理学生与 AI 的对话历史。

在“学数有道”的新定位下，对话历史不是普通聊天记录，而是认知诊断的数据证据。每一轮提问、追问、提示请求、学生修正和 AI 干预，都可能用于判断学生当前掌握了什么、卡在哪里、是否依赖提示。

## 双表设计

| 表 | 写入方 | 用途 | 内容 |
|----|--------|------|------|
| `chat_history` | 前端 | 历史展示 + 诊断语料 | 完整对话、页面标记、教材选择 |
| `chat_logs` | 后端 | 诊断队列 | 问答记录 + 分析状态标记 |

### chat_history（前端表）

前端在提问前创建记录（answer 初始为空），SSE 结束后后端通过 `_update_chat_answer_bg` 后台更新完整答案。

```
前端 POST /api/chat/save  → 创建记录（answer=""）
  ↓
后端 SSE 流式返回完成
  ↓
background_tasks: _update_chat_answer_bg(chat_id, full_response, thinking)
```

### chat_logs（后端表）

后端在每次问答完成后写入，含 `is_analyzed` 标记：

```
save_chat_log(user_id, sequence_id, question, answer, sources)
  → is_analyzed = 0（待诊断）
  → diagnostic_worker 消费后 → is_analyzed = 1
```

## 对话截断策略

| 位置 | 截断规则 | 原因 |
|------|---------|------|
| Prompt 历史 | 最近 6 轮，user ≤ 300 字，asst ≤ 2000 字 | 控制上下文窗口 |
| 诊断管线 | **不截断，全文传入** | 异步后台，上下文充裕 |
| 日志显示 | 全文存储 | 用于前端回看 |

这是 v2.4 的调整：诊断管线原先也截断到 200 字，现已移除三层截断。

## 诊断证据字段建议

后续可在对话或诊断快照中补充以下结构化字段：

| 字段 | 用途 |
|---|---|
| `turn_index` | 标记诊断依据来自第几轮对话 |
| `hint_level_used` | 记录学生需要几级提示 |
| `student_attempt` | 保存学生自己的关键尝试 |
| `diagnosed_breakpoint` | 本轮判断出的认知断点 |
| `evidence_span` | 支持诊断判断的原文片段 |

这些字段能帮助系统生成“判断依据”，避免诊断卡片看起来像模型臆测。

## API 端点

[chat.py](../app/routers/chat.py)：

| 端点 | 用途 |
|------|------|
| `POST /api/chat/save` | 保存新对话记录 |
| `PATCH /api/chat/{id}/answer` | 更新对话答案（SSE 完成后） |
| `PATCH /api/chat/{id}/thinking` | 更新思维链（thinking） |
| `GET /api/chat/history` | 获取用户对话历史 |
