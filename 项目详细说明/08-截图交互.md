# 08 — 截图交互

截图交互模块支持学生在 PDF 上框选题目区域，系统将截图发送给视觉语言模型（VL Model）识别并作答。

## 流程

```
学生框选 PDF 区域
  ↓
ScreenCapture 组件截取选中区域 → base64 图片
  ↓
POST /api/qa/solve-stream (image_data=base64)
  ↓
【阶段 1：结构化识别】
  prepare_screenshot_context 读取 PDF 原图区域（PDF 裁剪落盘，pdf_crop_path）
  QA_VL_MODEL（qwen3.6-plus）做结构化题目识别（vision_extraction）：
  - problem_text / formulas / diagram_description / question_intent / confidence / tool_ready
  - 定位上下文：在教材上下文中定位对应章节（sequence_id / chapter_name）
  ↓
【阶段 2：流式生成】
  识别可靠（tool_ready && confidence ≥ 阈值）→ 复用工具链路（ToolRuntime）
  识别不可靠 → 直接结合图片回答（recognition_fallback 阶段提示）
  QA_VL_MODEL（qwen3.6-plus）流式输出：
  - thinking: 思考过程（可选）
  - content: 最终回答
  ↓
前端实时渲染：
  - ChatPanel 显示 thinking（折叠） + 回答
  - ChatPanel 显示截图缩略图
```

## 关键设计

### 截图上下文缓存持久化

截图不是用完即弃：上下文缓存持久化到 `screenshot_context_cache` 表（connection.py L171-206），键为 `image_hash + textbook_id + page_number + crop_bbox_hash + full_context_hash`：

- **PDF 裁剪落盘**：`render_pdf_crop()` 把截图对应 PDF 原图区域裁剪成图片文件，路径存 `pdf_crop_path`（[pdf_cropper.py](../app/services/pdf_cropper.py)）；
- **识别结果缓存**：`vision_extraction`（结构化题目识别）与 `vision_summary` 字段持久化，同参截图（image_hash 相同）直接复用，不重复调用 VL 模型；
- **定位信号**：`locator_signals` 记录教材定位结果，`md_match_status / md_match_confidence` 记录与教材 MD 的匹配情况。

`sources` 数组同时记录了截图对应的教材位置信息，供后续诊断使用。

### VL 模型独立配置

文字问答和截图问答使用**独立的模型配置项**（当前默认均为 qwen3.6-plus，config.py L37/L57）：

| 路径 | 配置项 | 默认模型 | 调用方式 |
|------|--------|---------|---------|
| 文字 | `QA_LLM_MODEL` | qwen3.6-plus | OpenAI 兼容 API（QA_LLM_API_BASE） |
| 截图 | `QA_VL_MODEL` | qwen3.6-plus | DashScope 原生多模态（llm_service.vision_chat） |

单独配置 VL 模型是为了保证截图路径使用支持多模态输入的模型，避免通用对话模型不支持图片输入的兼容性问题。

### SSE 事件流

截图问答的 SSE 事件包括：

| event | data | 含义 |
|-------|------|------|
| `stage` | `{stage: "reading_pdf", ...}` | 正在读取 PDF 原图区域 |
| `stage` | `{stage: "recognizing", ...}` | 正在识别题目与公式（vision_extraction） |
| `stage` | `{stage: "locating", ...}` | 正在匹配教材上下文 |
| `stage` | `{stage: "generating", ...}` | 正在生成回答 |
| `stage` | `{stage: "recognition_fallback", ...}` | 结构化识别不可靠，直接结合图片回答 |
| `thinking` | `{delta: "..."}` | 思维链增量 |
| `text` | `{delta: "..."}` | 回答文本增量 |
| `tool_call` / `tool_result` | `{...}` | 工具链路调用（识别可靠时） |
| `visualization` | `{...}` | 数学可视化产物（工具链路） |
| `done` | `{sources, sequence_id, full_text, thinking}` | 完成，返回元信息 |
| `error` | `{error: "..."}` | 错误 |
| `heartbeat` | `{text: ""}` | 路由层每 15s 心跳，防前端超时断开 |

### vision_extraction 结构化题目识别

截图路径先做结构化题目识别（[vision_extraction.py](../app/services/qa/vision_extraction.py)），而不是直接让模型看图回答：

- 调 VL 模型返回严格 JSON（`VisionExtraction`，版本 `vision-extraction-v1`）：problem_text / formulas / diagram_description / question_intent / confidence / tool_ready；
- 结果按 `(cache_id, extraction_version, vision_model)` 缓存到 `screenshot_context_cache`，同参不重复识别（answer_service.py L245-313）；
- `tool_ready && confidence ≥ VISION_EXTRACTION_CONFIDENCE`（默认 0.70）时把识别结果格式化为题目文本，进入工具链路复用 ToolRuntime；否则回退到直接结合图片回答，并给 `recognition_fallback` 阶段提示。

结构化识别的意义：让"看图 → 做题 → 验算"走同一套工具链路（search_textbook / verify_math / create_math_visualization），而不是每次截图都靠模型自由发挥。

### 后台采集对齐

截图路径与文字路径共用同一套采集链路：

- `save_chat_log`：兼容写（turn_store 写入 chat_logs，`is_analyzed` 不再是诊断触发源）
- `update_knowledge_stats`：已无调用方，不再采集知识点统计
- 诊断：QA 回答结束后由 StreamBus 广播 done，诊断侧 `listen_qa_done` 触发 V2 分源评分（消费 `qa_turn_records`），另有 30s 轮询兜底（见 [01-智能问答](01-智能问答.md)）
- 页面标记：chat_history 写入（marker_type / thumbnail / crop_bbox / screenshot_context_id），SSE 完成后补 answer

### AiBall — 平板适配

平板竖屏时 PDF 全屏，没有侧边聊天栏。AiBall 是一个悬浮在右下角的圆形按钮：
- 点击展开 → 输入问题或框选截图
- 有未读回答时显示红点
- 回答面板从底部滑出（半屏）
