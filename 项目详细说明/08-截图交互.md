# 08 — 截图交互

截图交互模块支持学生在 PDF 上框选题目区域，系统将截图发送给视觉语言模型（VL Model）识别并作答。

## 流程

```
学生框选 PDF 区域
  ↓
ScreenCapture 组件截取选中区域 → base64 图片
  ↓
POST /api/qa/solve-stream (image_data=base64)
  ↓
【阶段 1：图片识别】
  QA_VL_MODEL（qwen-vl）识别图片内容：
  - sources: 在教材上下文中定位对应章节
  - 提取 sequence_id 和 chapter_name
  ↓
【阶段 2：流式生成】
  同上 QA_VL_MODEL 流式输出：
  - thinking: 思考过程（可选）
  - content: 最终回答
  ↓
前端实时渲染：
  - ChatPanel 显示 thinking（折叠） + 回答
  - ChatPanel 显示截图缩略图
```

## 关键设计

### 图片不存服务器

截图以 base64 格式在请求中传输，LLM 处理后丢弃。`sources` 数组记录了截图对应的教材位置信息，供后续诊断使用。

### VL 模型独立配置

文字问答和截图问答使用**不同的模型**：

| 路径 | 模型 | 配置 |
|------|------|------|
| 文字 | `QA_LLM_MODEL`（qwen3.5-plus） | OpenAI 兼容 API |
| 截图 | `QA_VL_MODEL`（qwen-vl） | DashScope MultiModalConversation API |

这避免了前端的 `qwen-max` 不支持 DashScope MultiModal 的兼容性问题。

### SSE 事件流

截图问答的 SSE 事件包括：

| event | data | 含义 |
|-------|------|------|
| `stage` | `{stage: "reading", text: "正在识别图片..."}` | 阶段切换 |
| `stage` | `{stage: "generating", text: "正在生成回答..."}` | 开始生成 |
| `thinking` | `{delta: "..."}` | 思维链增量 |
| `text` | `{delta: "..."}` | 回答文本增量 |
| `done` | `{sources, sequence_id, full_text, thinking}` | 完成，返回元信息 |

### 后台采集对齐

v2.3 修复后，截图路径与文字路径的采集行为一致：

- ✅ `save_chat_log`（含完整 answer）
- ✅ `update_knowledge_stats`（含 topic）
- ✅ `trigger_diagnostic_if_needed`（含 sequence_id）

### AiBall — 平板适配

平板竖屏时 PDF 全屏，没有侧边聊天栏。AiBall 是一个悬浮在右下角的圆形按钮：
- 点击展开 → 输入问题或框选截图
- 有未读回答时显示红点
- 回答面板从底部滑出（半屏）
