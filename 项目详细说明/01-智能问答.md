# 01 — 智能问答

智能问答是系统的主流程。学生通过文字或截图提问，系统组装结构化 Prompt，LLM 流式返回答案，后台自动采集行为数据。

在“学数有道”的新定位下，智能问答不只是回答问题，而是认知诊断的第一入口。每一次提问、追问、卡住、请求提示，都会成为判断学生知识掌握状态和认知断点的证据。

## 流程

```
POST /api/qa/solve-stream
  │
  ├─ 并发获取上下文:
  │   ├─ get_page_context(textbook_id, page)  → textbook_sections（教材上下文）
  │   ├─ get_whitelist(Neo4j)                 → 知识边界白名单
  │   └─ get_math_profile(SQLite)             → 15 维画像
  │
  ├─ get_prereq_gaps(sequence_id)             → 前置知识缺口
  ├─ get_stage(chapter_name)                  → 认知阶段
  │   └─ fallback: get_user_avg_stage()       → 全局平均 stage
  │
  ├─ scaffolding_controller.determine_level() → 学徒层级
  ├─ prompt_engine.build_prompt()             → 组装最终 Prompt
  │
  ├─ LLM 流式输出 (SSE → 前端)
  │
  └─ 后台采集:
      ├─ save_chat_log(全文)       → chat_logs
      ├─ update_knowledge_stats    → user_knowledge_stats
      └─ trigger_diagnostic_if_needed → 满 3 次触发诊断
```

## 10 路 Prompt 信号

[prompt_engine.py](../app/services/prompt_engine.py) 组装 System Prompt，按顺序注入：

| # | 信号段 | 来源 | 说明 |
|---|--------|------|------|
| 1 | 语言规则 | 硬编码 | 中文 + LaTeX 格式要求 |
| 2 | 角色段 | teaching_mode + socratic_submode | 苏格拉底/直接讲解 |
| 3 | 干预块 | latest_diagnostic_report | 如有 weak_node 则注入教学建议 |
| 4 | 知识白名单 | Neo4j whitelist | 限制 LLM 只使用已学概念 |
| 5 | 学生画像 | math_profiles | 年级 + 薄弱点 |
| 6 | 前置提醒 | prerequisite_checker | 最多 8 个前置薄弱概念 |
| 7 | 认知段 | knowledge_stages | 阶段对应的认知描述 |
| 8 | 困难提示 | scaffolding_controller | 零延迟关键词检测 |
| 9 | 学徒规则 | apprenticeship_level | MODELING→FADING 指令 |
| 10 | 对话历史 | chat_history | 最近 6 轮（user≤300, asst≤2000） |

最后拼接教材上下文和当前题目。

## 认知诊断视角

问答链路需要尽量保留以下信号，供诊断卡片和画像更新使用：

| 信号 | 用途 |
|---|---|
| 当前教材页和 sequence_id | 定位学生正在学习的课程位置 |
| Neo4j 白名单和前置概念 | 判断问题属于当前知识点还是前置缺口 |
| 对话历史和追问轮次 | 判断学生是没听懂、卡步骤，还是主动深入 |
| 请求提示次数 | 估计提示依赖度 |
| 回答中的关键错误 | 进入错因分析和后续练习推荐 |

因此，理想输出不应只有一段讲解，还应能在后台生成结构化诊断要素：相关知识点、卡点类型、判断依据、建议干预和后续练习方向。

## 四级学徒脚手架

[scaffolding_controller.py](../app/services/scaffolding_controller.py) 根据 `student_stage` 决定回答策略：

| 层级 | stage | 策略 | Prompt 指令 |
|------|-------|------|-----------|
| MODELING | 0-1, NULL | 完整示范 | "给出完整解题过程，每一步都解释原理" |
| COACHING | 2-3 | 引导练习 | "先让学生尝试，只在卡住时给出提示" |
| SCAFFOLDING | 4 | 最小支架 | "只提供关键提示，让学生自己完成推导" |
| FADING | 5 | 独立探索 | "只回答学生主动提出的问题，不主动展开" |

`student_stage` 由 `get_stage(chapter_name) or get_user_avg_stage()` 计算——先尝试精确匹配章节名，失败则用全局平均兜底。

## 前置知识检测

[prerequisite_checker.py](../app/services/prerequisite_checker.py) 通过 Neo4j 检测薄弱前置概念：

```
1. Neo4j: MATCH (n:Concept)-[:PREREQUISITE_OF]->(prereq)
     WHERE n 在当前节 → 获取前置概念列表
2. knowledge_stages: 查询每个前置概念的 stage
3. 判断：stage IS NULL OR stage ≤ 2 → is_gap = true
4. 最多 8 个 gap 概念 → 生成提醒块注入 Prompt
```

Section 匹配使用 STARTS WITH（5 级 ID 格式：`V1-C01-S03-U00-T00`）。

## 双模式支持

| 模式 | 触发 | LLM | Prompt 差异 |
|------|------|-----|------------|
| 文字 | `image_data` 为空 | QA_LLM (qwen3.5-plus) | 标准 Prompt |
| 截图 | `image_data` 有值 | QA_VL_MODEL (qwen-vl) | 加 `has_image=True` 要求对照教材上下文提取公式 |

截图路径走独立的 `solve_with_vision_stream()`，完成后同样触发统计计数和诊断。
