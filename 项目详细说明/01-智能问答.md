# 01 — 智能问答

智能问答是系统的主流程。学生通过文字或截图提问，系统组装结构化 Prompt，LLM 流式返回答案，后台自动采集行为数据。

在"学数有道"的新定位下，智能问答不只是回答问题，而是认知诊断的第一入口。每一次提问、追问、卡住、请求提示，都会成为判断学生知识掌握状态和认知断点的证据。

## 主流程（QAAgent → ToolRuntime 工具链路）

路由层 `POST /api/qa/solve-stream` 收到请求后调用 `QAAgent().run()`，由 Agent 按输入类型选路：

```
QAAgent.run(QATurnInput)
  ├─ input_type == "text" 且存在工具定义
  │    └─ answer_turn_with_tools()（默认文本路径，工具链路）
  │         ├─ ground_text_turn()               # KG 定位：教材页 → section → 概念/前置/规则案例
  │         ├─ intervention_service.compose_for_turn()  # 学生状态 + 教学策略（兜底走 tutor_policy）
  │         ├─ scaffolding_controller.determine_level() # 脚手架层级，写入 QATurnRecord
  │         ├─ prompt_builder.build_lightweight_prompt() # 精简 Prompt（最近 3 轮历史）
  │         ├─ ToolRuntime.run()                # 有界工具循环：search_textbook / lookup_kg_node /
  │         │                                   #   verify_math / create_math_visualization
  │         │                                   #   SSE 事件：tool_call / tool_result / visualization
  │         └─ 回答结束：StreamBus.emit(done)
  │              ├── start_persist_consumer()   # 异步持久化 QATurnRecord（不阻塞 SSE）
  │              └── listen_qa_done()           # 诊断消费者（自行触发 V2 诊断）
  │
  └─ 截图（image / mixed）
       └─ answer_turn() → _answer_vision_turn()
            ├─ vision_extraction.extract_vision_problem()  # 结构化识别题目
            ├─ 识别可靠（tool_ready 且 confidence ≥ 阈值）
            │    └─ answer_turn_with_tools()   # 复用工具链路
            └─ 不可靠 → _answer_vision_direct()  # 直接结合图片回答（build_vision_prompt，最近 6 轮）
```

超时边界：`QAAgent` 按输入类型套用超时（`QA_TEXT_TURN_TIMEOUT_SECONDS` / `QA_SCREENSHOT_TURN_TIMEOUT_SECONDS`，0 表示不限），超时 `yield sse_error`。

## ToolRuntime 工具链路

默认文本路径走工具化入口（`answer_service.answer_turn_with_tools`），而不是直接调 LLM。核心特性：

- **三道硬边界**（`ToolRuntimeConfig`，默认值可环境变量覆盖）：
  - `max_model_rounds=5`：模型最多 5 轮工具循环；
  - `max_total_calls=8`：整轮最多 8 次工具调用；
  - `max_consecutive_failure_rounds=2`：连续 2 轮失败即降级收尾。
- 超出边界进入降级收尾（`degraded` + `degradation_code`：`tool_budget_exceeded` / `tool_failures` / `tool_round_limit`），强制模型只用已有结果收尾。
- **4 个 QA 工具**：`search_textbook`（查教材原文）、`lookup_kg_node`（查 KG 节点/邻接）、`verify_math`（SymPy 验算）、`create_math_visualization`（数学可视化）。
- 同参调用按 fingerprint 去重；每次调用写 `tool_call_traces` 表（参数脱敏），并通过 `tool_call` / `tool_result` SSE 事件推给前端。
- 可视化产物经 `artifact_handler` 落库到 `math_visualizations`，以 `visualization` SSE 事件推送。

## Prompt 三入口

[prompt_builder.py](../app/services/qa/prompt_builder.py) 提供三个 Prompt 构造器：

| 入口 | 使用场景 | 历史窗口 | 说明 |
|------|---------|---------|------|
| `build_lightweight_prompt` | **默认文本路径**（工具链路） | 最近 3 轮 | 精简版：去教材全文（LLM 可用 search_textbook 按需查），保留 KG 证据、学生状态、教学策略、可视化工具规则 |
| `build_tutor_prompt` | 非工具文本路径（`answer_turn` 兜底） | 最近 3 轮 | 完整版：教材定位 + 内容片段 + KG 命中详情 + 教材证据 + 学生状态 + 教学策略 + 历史 |
| `build_vision_prompt` | 截图直接回答路径 | 最近 6 轮 | 视觉版：整合 10 路教学信号（角色、教学规则、认知感知、零延迟检测、前置提醒、干预块、白名单、画像、教材上下文、历史），要求扫描教材上下文中的 LaTeX 公式 |

历史窗口说明：`_format_history()` 固定取 `history[-3:]`（最近 3 轮）；视觉版在 build_vision_prompt 内部取 `history[-6:]`（最近 6 轮）。

## KG 上下文（KGContext）

每次提问由 `ground_text_turn()` 组装 `TurnGrounding`，其中 `kg_context`（`KGContext` dataclass，来自 `diagnosis/contracts.py`）提供结构化 KG 信息，供 Prompt 注入：

| 字段 | 内容 |
|------|------|
| `current_nodes` | 本节核心概念（scope=current） |
| `question_matches` | 问题文本命中节点 |
| `support_nodes` | 支撑/前置概念（当前节之前，scope=allowed） |
| `lookahead_nodes` | 后续展望概念（scope=lookahead，只在学生主动问时点到为止） |
| `relations` | 支撑关系（source --rel_type--> target） |
| `rule_cases` | 规则案例（条件-结论结构，用于组织严谨步骤） |

KG 使用边界写入 Prompt：KG 只作为教材索引、术语边界、关系约束和规则条件参考；若 KG 与当前页原文不一致，以当前页原文为准。

## 截图结构化识别

截图路径先走 `vision_extraction.extract_vision_problem()`（answer_service.py `_answer_vision_turn`，L245-313）：

1. 读取 PDF 原图区域（`prepare_screenshot_context`）→ 命中/缓存定位上下文；
2. 调视觉模型（qwen3.6-plus）做**结构化题目识别**，返回带版本号 `vision-extraction-v1` 的 `VisionExtraction` 对象（problem_text / formulas / diagram_description / question_intent / confidence / tool_ready）；
3. 识别结果按 `(cache_id, extraction_version, vision_model)` 缓存到 `screenshot_context_cache`，避免重复识别；
4. `tool_ready && confidence ≥ VISION_EXTRACTION_CONFIDENCE` 时走工具链路（复用 ToolRuntime）；否则回退到直接结合图片回答，并给出 `recognition_fallback` 阶段提示。

## SSE 事件

路由层通过 `EventSourceResponse` 推送，事件格式统一为 `{event, data}`：

| 事件 | 说明 |
|------|------|
| `stage` | 阶段提示（searching / planning / generating / reading_pdf / recognizing / locating ...） |
| `content` | 正文 token（流式） |
| `done` | 完整回答 + sources + sequence_id + qa_turn_id（工具路径另含 visualizations / tool_stats / degraded） |
| `error` | 错误 |
| `heartbeat` | 路由层每 15s 注入，防止前端超时断开 |
| `tree_turn_started` | 树对话回合开始（携带 tree_id / node_id / turn_id） |
| `tool_call` | 工具调用开始 |
| `tool_result` | 工具调用结果 |
| `visualization` | 数学可视化产物 |

## 对话树参数

树对话由路由层识别并开启（`app/db/chat_tree_db.py`）：

- 请求参数：`client_turn_id`（必填）+ `node_id`（必填）+ `tree_id` / `fork_message_id` / `referenced_node_ids` / `expected_node_revision`；
- 校验：树对话要求 Bearer token，`client_turn_id` / `node_id` 缺失返回 422；
- 流程：`begin_turn()` 创建持久化回合（含 assistant 占位）→ `tree_turn_started` 事件 → 回答完成后 `finish_turn()` 写回内容；
- 历史构建：服务端用 `get_authorized_context()` 构建 `authorized_history`（当前节点路径 + 显式引用分支），客户端历史不作为信任输入；
- 幂等：同一 `client_turn_id` 重复提交返回已有回合；已完成回合直接回放答案，不重复调用 LLM。

## 诊断消费者

QA 不触发诊断、不更新 stage。回答结束后通过 per-turn `StreamBus` 广播 done 事件，诊断侧自行订阅：

```
bus.emit({"type": "done"})
  ├─ 持久化消费者（start_persist_consumer）：异步写 qa_turn_records，失败自动重试 1 次
  └─ 诊断消费者（listen_qa_done）：
       ├─ 等待持久化完成（persist_done），确保能读到刚写入的记录
       ├─ 获取 user_id 级诊断锁，防止事件触发与轮询并发
       └─ run_diagnostic_batch(user_id) → V2 分源评分（qa_stage / qa_dimension scorer）
```

`diagnostic_worker` 另有 30s 轮询兜底（`DIAGNOSTIC_CHECK_INTERVAL=30`），保证事件总线故障时诊断不中断。

## 持久化

`turn_store.save_turn_record()` 采用三存储层：

| 存储 | 角色 |
|------|------|
| `qa_turn_records` | 主表：完整结构化上下文（context_snapshot / messages_snapshot / prompt_preview / model_name / latency_ms） |
| `chat_logs` | 兼容写：旧诊断 worker 仍依赖 |
| `chat_history` | 兼容写：前端已创建 chat_id 时，SSE 完成后补 answer / thinking / screenshot_context_id |

回答中途异常时兜底生成带 `error` 字段的 `QATurnRecord`，并 `yield sse_error`，保证前端能拿到明确错误而不是挂起。

## 前置知识检测

[prerequisite_checker.py](../app/services/prerequisite_checker.py) 通过 Neo4j v4.4 检测薄弱前置概念，当前实现：

```
1. 构造 section_node_id：section_node_id(textbook_id, sequence_id)
   → 格式 "教材id:Cxx:Sxx[:Uxx]"（app/textbooks.py）
2. prerequisite_candidates_for_section(section_node_id)
   → 取本节核心概念，沿 SUPPORT_REL_TYPES 一跳邻接去重，返回前置候选名列表
3. knowledge_stages：查询每个前置概念的 stage
4. 判断：stage IS NULL OR stage ≤ 2 → is_gap = true
5. 组装前置提醒块注入 Prompt（最多 8 个）
```

`get_prereq_gaps` 先走 KG 候选；KG 不可用时回退到 `related_nodes`（支撑/扩展邻接）兜底。

## 四级学徒脚手架

[scaffolding_controller.py](../app/services/scaffolding_controller.py) 根据 `student_stage` 决定回答策略：

| 层级 | stage | 策略 | Prompt 指令 |
|------|-------|------|-----------|
| MODELING | 0-1, NULL | 完整示范 | "给出完整解题过程，每一步都解释原理" |
| COACHING | 2 | 引导练习 | "先让学生尝试，只在卡住时给出提示" |
| SCAFFOLDING | 3-4 | 最小支架 | "只提供关键提示，让学生自己完成推导" |
| FADING | 5 | 独立探索 | "只回答学生主动提出的问题，不主动展开" |

`student_stage` 由 `get_stage(chapter_name) or get_user_avg_stage()` 计算——先尝试精确匹配章节名，失败则用全局平均兜底。submode 可微调层级偏移；视觉 Prompt 构造时 Socratic 模式下 MODELING 会降为 COACHING（不强制给完整答案，见 prompt_builder.build_vision_prompt）。
