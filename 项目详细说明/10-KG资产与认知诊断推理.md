# 10 — KG 资产与认知诊断推理

本文档记录 v4.4 教材知识图谱中的结构性资产，以及这些资产在应用层的消费现状（已实现）与待办（未接通的能力）。它是 [09-竞赛定位与认知诊断闭环.md](./09-竞赛定位与认知诊断闭环.md) 中诊断卡片、断点定位和效果验证的物理基础。

## 一、v4.4 构建管线概览

v4.4 是一套 **27 个编号脚本（00~09）的多轮 LLM 流水线**，从丘维声《高等代数》和黄立宏《高等数学》结构化 Markdown 出发，产出可入库的知识图谱。脚本位于 `教材提取模块/高代提取/`（含配置、教材树、小节摘要、显式节点/边提取、规则案例提取、全局归一化、AI 评审门禁、汇总成图、Neo4j 导入、应用验证），构建流程说明见 `教材提取模块/高代提取/v4.4_step说明.md`。

当前图谱规模（据 [README.md](../README.md)）：

- 节点：2,980
- 边：4,396
- 节点类型：9 种（Concept / Theorem / Formula / Method / ProblemClass / RuleCase / ConditionExpression / Outcome / KnowledgeGroup）
- 边类型：16 种（核心层 8 + 规则层 4 + 知识组层 2 + 派生层 2）
- 覆盖教材：高等代数上册、高等代数下册（与上册合并部署）、高等数学上册、高等数学下册

## 二、三大结构性资产

这三项是 v4.4 的结构性优势，也是应用层诊断可溯源、可验证的物理基础。前两项已接入应用层（见第三节）。

### 资产 1：节点带 `source_code` + `evidence_span`

每个核心节点都带两个溯源字段：

| 字段 | 含义 | 示例 |
|---|---|---|
| `source_code` | 紧凑来源编码，指向教材具体小节 | `gaodai_shang:C03:S05:U01` |
| `evidence_span` | 教材原文片段 | "由 s·m 个数排成 s 行、m 列的一张表称为一个 s×m 矩阵" |

代码位置：`kg_v44.py` 的 `_node_map` 把这两个字段从 Neo4j 读出并返回给所有查询函数。`find_node`、`nodes_for_section`、`related_nodes` 均返回它们。

**意义**：诊断结论可以追溯到丘维声教材的具体小节段落，而不是停留在"你薄弱的概念是矩阵的秩"。这让"认知断点诊断"从 LLM 猜测变成有教材出处的可验证判断。

### 资产 2：规则案例层

v4.4 把数学中的条件判断结构化为一组专门的关系，而不是压成一条普通边。结构如下：

```text
定理/公式/方法
  --HAS_RULE_CASE--> 规则案例 RuleCase
  规则案例 --APPLIES_TO--> 适用对象
  规则案例 --HAS_CONDITION--> 条件表达式 ConditionExpression
  规则案例 --HAS_OUTCOME--> 结论/状态 Outcome
  条件表达式 --REFERS_TO--> 核心知识点
```

示例（来自 v4.4_step说明.md）：

```text
线性方程组解的判定定理 --HAS_RULE_CASE--> 无解判定
无解判定 --APPLIES_TO--> 非齐次线性方程组
无解判定 --HAS_CONDITION--> r(A)<r(A|b)
无解判定 --HAS_OUTCOME--> 线性方程组无解
```

节点类型 `RuleCase`、`ConditionExpression`、`Outcome` 已在 Neo4j 中存在（9 种节点类型之一）。

**意义**：当学生做错一道线性方程组解的判定题时，系统可以定位到涉及哪个规则案例，进一步判断学生是对条件理解错了（没验证 r(A)<r(A|b)），还是对结论理解错了，还是对适用对象判断错了。这是结构化推理，不是 RAG 文本检索。对手的 KG 把"若 A 则 B"压成一条边或扔进 RAG 文本，丢了条件结构。

### 资产 3：三层关系架构

v4.4 把关系分为三层：

| 层 | 关系类型 | 用途 |
|---|---|---|
| 核心普通关系层 | SUPERIOR / EQUATIVE / PART_OF / HAS_PROPERTY / USES / GETS / DERIVES / REFERS_TO | 学习路径、概念依赖、方法推荐 |
| 条件判断规则层 | HAS_RULE_CASE / APPLIES_TO / HAS_CONDITION / HAS_OUTCOME | 条件推理、错因定位 |
| 知识组导航层 | HAS_MEMBER / HAS_ANCHOR | 按小节或规则主题组织节点 |

另有派生/展示层 `PREREQUISITE_OF` 和 `HAS_POSSIBLE_STATE`，v4.4 定义为"可从核心图与规则层推导"，但当前未实现派生逻辑（应用层用一跳邻接代替严格前置链）。

**意义**：不同教学用途走不同层。学习路径走核心层，错因诊断走规则层，章节导航走知识组层。对手的 KG 是扁平的，学习路径和例题推荐混在一起。

## 四、三个杀手级能力 → 代码路径

把上述资产接入应用层后，可形成三个对手没有的能力。

### 能力 1：诊断可溯源（已实现）

**叙事**：系统说"你卡在矩阵的秩"，同时说"这个概念定义在丘维声《高等代数》上册第 3 章第 5 节第 1 单元，判断依据是教材原文……"。

**代码路径（已接通）**：
- `kg_v44.find_node(name)` 返回 `source_code` 和 `evidence_span`；
- `GET /api/auth/diagnostic-cards`（auth.py）对 stage ≤ 2 且有 evidence 的概念查 `find_node`，用 `parse_source_code`（textbook_section_db.py）解析出 `source_display` / `textbook_name`；
- 前端 [DiagnosticCard.tsx](../frontend/src/components/DiagnosticCard.tsx) 展示"教材出处"（source_display）与"判断依据"（evidence_span）；
- QA Prompt 的教材证据段（evidence_lines）同样注入 `EvidenceSpan`（source_code + 原文片段）。

**后续增强**：`source_code → 页码` 的精确解析已有 `parse_source_code` 基础，可进一步在卡片上显示起始页。

### 能力 2：规则案例推理（已实现）

**叙事**：学生做错线性方程组解的判定题 → 系统定位到涉及"无解判定"规则案例 → 检查学生是否验证了条件 r(A)<r(A|b) → 输出"你用了无解判定，但前提 r(A)<r(A|b) 没有验证。请先算两个矩阵的秩。"

**代码路径（已接通）**：
- `kg_v44.get_rule_cases_for_node(concept_name)` 返回该节点关联的所有规则案例（含条件、结论、适用对象）；
- `error_analyzer._build_rule_cases_block` 把命中的规则案例结构化注入错因分析 Prompt，让 LLM 判断学生是"条件理解错误 / 条件→结论映射错误 / 适用对象错误"，而不是自由文本猜测；
- QA grounding 对规则案例按 scope 与相关性排序后注入 `KGContext.rule_cases`，Prompt 提示"先核验适用条件，再使用对应结论"；
- 诊断卡片返回 `rule_cases` 数组，前端可展示涉及的条件。

**后续增强**：目前规则案例由 LLM 结合注入的块做推理；可进一步做程序化条件比对（学生作答中是否出现条件关键字）。

### 能力 3：教材级闭环（各环节已实现，链路未串）

**叙事**：学生卡题 → 定位到 KG 节点（带 source_code）→ 查规则案例判断断点类型 → source_code 指向教材具体小节 → 从教材题池推荐原题 → 学生做题 → 练习证据回流诊断 → 重新检查前置链是否打通。

**代码路径（各环节现状）**：
- 诊断 → `find_node` 返回 `source_code` → 解析为 `sequence_id`（parse_source_code）；
- 推荐练习 → `exercise_items`（source='textbook'）从已审核教材题池取题，按 sequence_id 过滤，经 `kg_validation` 校验 KG 映射；
- 学生做题 → exercise 提交写 `exercise_attempts`（V2 直接消费）；practice 会话作答写 `practice_attempts` 并触发诊断批次 → 证据账本；
- 前置重查 → `prerequisite_checker` 基于 `prerequisite_candidates_for_section` 重新检查。

**待办**：把上述环节串成一条端到端演示链路（含前端入口跳转）。

## 六、与 09 文档的关系

09 文档定义了认知诊断闭环的叙事主线和诊断卡片形态。本文档补充了诊断卡片的物理基础：

- "判断依据"字段 ← `evidence_span`（教材原文片段，已消费）
- "教材出处"字段 ← `source_code`（教材小节坐标，已消费）
- "错因类型"字段 ← 规则案例层的条件检查（已消费，错因分析注入规则案例）
- "后续练习"字段 ← practice 教材题池（`exercise_items`，已实现选题与 KG 映射校验）

09 中的"效果验证"部分（诊断一致率、提示后修正率）也应基于本文档的溯源能力：系统诊断是否与教师诊断一致，关键看系统能否定位到与教师相同的规则案例和条件断点。
