# 02 — 学生画像

学生画像是系统的自适应核心。双层模型：上层 15 维素养评估综合能力，下层 per-concept 六阶段追踪每个知识点的掌握度。诊断引擎从对话与练习中自动提取信号，驱动脚手架策略和知识图谱展示。

在"学数有道"的新定位下，画像不能只被理解为"记住学生信息"。它要把学生的学习痕迹结构化为知识状态、错因类型、认知断点和提示依赖度，用于回答"学生为什么不会"。

## 双层模型

```
上层 — 五维素养（math_profiles）
  5 维度 × 3 标尺 = 15 个连续指标，LLM 评分 0-3
  用途：Prompt 干预、雷达图展示、学习洞察

下层 — 六阶段追踪（knowledge_stages）
  每个概念一个 stage（0-5），由确定性投影器按证据更新
  用途：脚手架层级、前置缺口检测、知识图谱
```

## 新增画像解释口径

| 画像对象 | 不是 | 而是 |
|---|---|---|
| 对话历史 | 简单聊天记录 | 判断学生卡点和认知变化的证据 |
| 知识点 stage | 粗略掌握度分数 | 可追踪、可审计、可重放的认知阶段 |
| weak_points | 用户手填薄弱点 | 系统从对话、错题、练习中诊断出的薄弱节点 |
| 15 维素养 | 装饰性雷达图 | 对抽象、推理、符号、表征、建模能力的长期估计 |
| 诊断报告 | 学习总结 | 后续追问、提示和练习推荐的依据 |
| 诊断证据 | LLM 单次猜测 | 每条画像更新的依据，可追溯到学生原文与教材出处 |

## 五维数学素养

| 维度 | 代码 | 含义 |
|------|------|------|
| 数学思考与抽象思维 | MT | 从具体实例抽象出一般数学结构 |
| 逻辑推理与论证 | LR | 构建严密逻辑链条、完成证明 |
| 符号形式化与算子运算 | SO | 运用数学符号进行形式化运算 |
| 多重表征与直观映射 | MR | 在不同表征形式之间转换 |
| 跨域建模与问题解决 | PS | 将实际问题建模为数学问题并求解 |

每个维度从三个指标评分（0-3）：

| 指标 | 含义 |
|------|------|
| coverage（覆盖广度） | 该维度下掌握的概念范围 |
| radius（迁移半径） | 将知识迁移到新情境的能力 |
| technical（技术深度） | 处理复杂问题的深度 |

## 六阶段认知追踪

| stage | 含义 | 典型表现 |
|-------|------|---------|
| 0 | 未接触 | 从未问过该概念 |
| 1 | 入门 | 能复述定义，问"是什么" |
| 2 | 理解 | 能解释原因，问"为什么" |
| 3 | 应用 | 能做标准题，问"怎么做" |
| 4 | 分析 | 能分析变式、比较不同解法 |
| 5 | 综合 | 能跨概念迁移、独立证明 |

## 诊断 V2：写入路径（唯一允许更新画像的架构）

V1 已归档到 `app/legacy/diagnosis_v1/`（单次混合 LLM 直接写画像，不可审计）。**V2 是唯一允许生产画像更新的路径**：分源评分 → 证据账本 → 确定性投影。当前发布档位为 `shadow`（`DIAGNOSIS_V2_MODE=shadow` 默认），只记录证据不修改画像。

```
路径 A：QA 证据
  qa_turn_records → QA 适配器（adapters.py）
    → qa_stage 评分器 / qa_dimension 评分器（scorers.py，独立 Prompt/Schema/版本）
    → diagnostic_evidence 证据账本（含 strength 与 student_quote）

路径 B：练习证据
  exercise_attempts → 练习适配器（adapters.py）
    → exercise_stage 评分器 / exercise_dimension 评分器（scorers.py）
    → diagnostic_evidence 证据账本

统一投影：
  StageObservation → Stage 投影器 → knowledge_stages
  DimensionObservation → 同章节五事件窗口 → math_profiles
```

**关键规则**（详细见 [docs/design/diagnosis-README.md](../docs/design/diagnosis-README.md)）：

- **分源评分**：四个评分器（`qa_stage` / `qa_dimension` / `exercise_stage` / `exercise_dimension`）各自独立 Prompt、Schema、版本号（`SCORER_VERSION`），一个来源失败不影响另一个。
- **确定性投影权重**：`certain=1.0` / `probable=0.5`；第一条强反证只降置信度，两条不同事件的强反证才降一级；`hypothesis` 只入账，不进长期画像。
- **引文校验**：引用必须是学生原文/学生答案的精确子串；Stage 概念必须逐字命中 KG，KG 为空时不产生 Stage 观察。
- **素养聚合**：单条维度观察不更新画像；同章节累计五个不同事件、每个分面至少 3 个事件、同向权重 ≥ 2/3 且 ≥ 2.0 才调整一级。
- **发布档位**：`shadow`（当前，默认）→ `stage_only`（开 Stage 投影）→ `full`（再开素养聚合）。
- **审计三件套**：`diagnosis_runs`（评分运行）、`diagnostic_evidence`（证据账本）、`state_projection_log`（投影前后值），提供幂等、审计和离线重放能力。

**后台触发**：

- `listen_qa_done()`：订阅 QA 的 StreamBus done 事件，等待持久化完成后实时触发（user_id 级锁防并发）；
- `diagnostic_worker_loop()`：30s 轮询兜底（`DIAGNOSTIC_CHECK_INTERVAL=30`）；
- 练习证据：`exercise.py` 提交时 `save_exercise_attempt` 写 `exercise_attempts`（V2 直接消费）；practice 会话作答写 `practice_attempts`（practice 自身证据），提交后触发 `run_diagnostic_for_user` 批量处理待评分源。

### 对话概率状态（影子消费者）

证据账本旁还有独立的对话概率状态影子消费者（`dialogue_state.py`）：

- 只消费已校验的 QA Stage 证据，为"用户-知识点"维护 Stage 0-5 概率分布（ordinal-bayes），写入 `dialogue_knowledge_states`；
- 模型给出 `accepted|abstained` 语义决定（含同义改写、跨轮提示、复述 AI 的独立性判断），程序只对 accepted 且独立证据更新分布；
- **不读写 `knowledge_stages`、不进 QA Prompt / 画像 API / 前端，只记录不生效**；
- 由 `DIALOGUE_STATE_MODE=off|shadow` 控制（默认 shadow），模型版本由 `DIALOGUE_STATE_MODEL_VERSION` 固定，支持按用户离线重放。

## 读取与使用

| 使用方 | 方式 | 影响 |
|--------|------|------|
| intervention_service | compose_for_turn 组装 StudentStateSummary | 教学策略 + QA Prompt 风格 |
| scaffolding_controller | `get_stage(chapter_name) or get_user_avg_stage()` | 四级学徒层级 |
| prerequisite_checker | `get_stages_batch(prereq_names)` | 前置概念是否缺口 |
| 知识图谱 API | stage ≤ 2 的概念 | 薄弱点图谱展示 |
| 诊断卡片 API | stage ≤ 2 且有 evidence 的概念 | 卡片 + 教材出处 |

QA 侧对 stage 只读不写：`StudentStateSummary` / `KGContext` 来自 `diagnosis/contracts.py`，用于调整回答风格，不更新 stage、不生成诊断结论。

## 前端可视化（6 Tab）

ProfilePanel 当前 6 个 Tab（[ProfilePanel.tsx](../frontend/src/components/ProfilePanel.tsx)）：

| Tab | 组件 | API | 说明 |
|-----|------|-----|------|
| 五维雷达 | RadarChart | `GET /api/auth/math-profile` | 15 维均值雷达图 |
| 学习轨迹 | LearningTrajectory | `GET /api/auth/diagnostic-history` | 诊断时间线 |

| 知识图谱 | KnowledgeGraph | `GET /api/auth/knowledge-graph` | 薄弱概念前后置链 |

**ProfilePanel 交互**：默认不展示编辑表单，年级和薄弱知识点不是每次打开画像时看到的。Header 有轻量"编辑资料"按钮，点击后出现仅含年级的编辑区。取消不关闭弹窗，只退出编辑模式。薄弱点来自系统诊断，不要求用户手填。

## 关键表（V2 新增）

| 表 | 内容 |
|----|------|
| `diagnosis_runs` | 每次评分运行（source_type + source_id + scorer_type + scorer_version 幂等唯一） |
| `diagnostic_evidence` | 证据账本（observation_type / concept_name / observed_stage / dimension / facet / strength / student_quote） |
| `diagnostic_signals` | 学习信号（concept_confusion / prerequisite_gap / procedural_error / hint_dependency / practice_request / insufficient_evidence） |
| `diagnosis_snapshots` | 评分快照（state_payload + signal_ids，发布给干预控制面） |
| `dimension_windows` | 素养同章节五事件聚合窗口 |
| `state_projection_log` | 每次投影 before/after（evidence_id + projection_type + projection_version 唯一） |
| `dialogue_knowledge_states` | 对话概率状态（"用户-知识点" Stage 0-5 概率分布） |
| `dialogue_state_projection_log` | 对话概率状态投影日志 |
| `exercise_attempts` | 练习作答证据（is_correct / hint_level / error_analysis / grader_version） |
| `qa_turn_records` | QA 事实记录（诊断的 QA 证据源） |
