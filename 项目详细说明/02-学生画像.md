# 02 — 学生画像

学生画像是系统的自适应核心。双层模型：上层 15 维素养评估综合能力，下层 per-concept 六阶段追踪每个知识点的掌握度。诊断引擎从对话中自动提取信号，驱动脚手架策略和知识图谱展示。

在“学数有道”的新定位下，画像不能只被理解为“记住学生信息”。它要把学生的学习痕迹结构化为知识状态、错因类型、认知断点和提示依赖度，用于回答“学生为什么不会”。

## 双层模型

```
上层 — 五维素养（math_profiles）
  5 维度 × 3 标尺 = 15 个连续指标，LLM 评分 0-3
  用途：Prompt 干预、雷达图展示、学习洞察

下层 — 六阶段追踪（knowledge_stages）
  每个概念一个 stage（0-5），LLM 每次诊断输出
  用途：脚手架层级、前置缺口检测、知识图谱
```

## 新增画像解释口径

| 画像对象 | 不是 | 而是 |
|---|---|---|
| 对话历史 | 简单聊天记录 | 判断学生卡点和认知变化的证据 |
| 知识点 stage | 粗略掌握度分数 | 可追踪的认知阶段 |
| weak_points | 用户手填薄弱点 | 系统从对话、错题、练习中诊断出的薄弱节点 |
| 15 维素养 | 装饰性雷达图 | 对抽象、推理、符号、表征、建模能力的长期估计 |
| 诊断报告 | 学习总结 | 后续追问、提示和练习推荐的依据 |

后续应补充“错因类型”和“提示依赖度”两类数据，使画像更接近认知诊断，而不仅是问答统计。

## 五维数学素养

| 维度 | 代码 | 含义 |
|------|------|------|
| 数学思考与抽象思维 | MT | 从具体实例抽象出一般数学结构 |
| 逻辑推理与论证 | LR | 构建严密逻辑链条、完成证明 |
| 符号形式化与算子运算 | SO | 运用数学符号进行形式化运算 |
| 多重表征与直观映射 | MR | 在不同表征形式之间转换 |
| 跨域建模与问题解决 | PS | 将实际问题建模为数学问题并求解 |

每个维度从三个指标评分（0-3）：

| 指标 | 含义 |
|------|------|
| coverage（覆盖广度） | 该维度下掌握的概念范围 |
| radius（迁移半径） | 将知识迁移到新情境的能力 |
| technical（技术深度） | 处理复杂问题的深度 |

## 六阶段认知追踪

| stage | 含义 | 典型表现 |
|-------|------|---------|
| 0 | 未接触 | 从未问过该概念 |
| 1 | 入门 | 能复述定义，问"是什么" |
| 2 | 理解 | 能解释原因，问"为什么" |
| 3 | 应用 | 能做标准题，问"怎么做" |
| 4 | 分析 | 能分析变式、比较不同解法 |
| 5 | 综合 | 能跨概念迁移、独立证明 |

### 写入路径

```
路径 A: 诊断管线（主力）
  Q&A ≥3 次同一话题 + 24h 锁
  → run_diagnostic_pipeline()
    → LLM 分析对话 → concept_stages [{name, stage, evidence}]
    → update_stage(override=stage)
    → pending_stage_updates → pending_worker(60s) → knowledge_stages

路径 B: 练习题批改
  学生提交答案 → error_analyzer 识别错因
  → update_stage(delta=-1)  ← 错则降级
  → pending_stage_updates → knowledge_stages
```

### 读取与使用

| 使用方 | 方式 | 影响 |
|--------|------|------|
| scaffolding_controller | `get_stage(chapter_name) or get_user_avg_stage()` | 四级学徒层级 |
| prerequisite_checker | `get_stages_batch(prereq_names)` | 前置概念是否缺口 |
| prompt_engine | 认知段文字 | Prompt 中阶段指导 |
| 知识图谱 API | stage ≤ 2 的概念 | 薄弱点图谱展示 |

## 诊断双管线

### 实时管线

[diagnostic.py](../app/db/diagnostic.py) — 每次问答后检查：

- 条件：`consecutive_turns ≥ 3` 或 `total_asks ≥ 5` + 距上次诊断 > 24h
- 时机：`asyncio.create_task` 异步后台
- 数据源：`chat_history`（前端表）
- 概念列表：`get_concepts_by_sequence_id(sequence_id)`（Neo4j STARTS WITH）

### 批量管线

[diagnostic_worker.py](../app/services/diagnostic_worker.py) — 每 300s 轮询：

- 条件：`chat_logs.is_analyzed = 0` 的记录 ≥ 5 条 + 24h 锁
- 数据源：`chat_logs`（后端表）
- 按 `sequence_id` 分组，每组独立诊断

### Pipeline 流程（两者共用）

```
1. get_concepts_by_sequence_id(sequence_id) → 章节概念列表（注入 Prompt）
2. get_user_recent_chats(topic, limit=10) 全文 → 不截断
3. LLM (Profile LLM) 输出:
   - dimension_deltas: 5 维度 × 3 标尺的增量（clamp 0-3）
   - weak_concepts: 薄弱概念列表
   - summary: 诊断摘要（100 字内）
   - concept_stages: [{name, stage: 0-5, evidence}]  ← v2.4 新增
4. update_diagnostic_report → math_profiles（增量累计）
5. save_diagnostic_assessment → question_assessments（快照）
6. update_stage(override=stage) → pending_stage_updates → knowledge_stages
```

### Delta 累积

评分采用增量式以避免单次误判：`new_val = current + delta → clamp(0,3)`。每次诊断传入最近对话，LLM 判断这次表现相比上次是进步还是退步。

## 前端可视化（5 Tab）

| Tab | 组件 | API | 说明 |
|-----|------|-----|------|
| 五维雷达 | RadarChart | `GET /api/auth/math-profile` | 15 维均值雷达图 |
| 学习轨迹 | LearningTrajectory | `GET /api/auth/diagnostic-history` | 诊断时间线 |
| 薄弱点 | WeakPointGraph | math_profile.weak_points | 待补强卡片列表 + 高频关注 |
| 知识图谱 | KnowledgeGraph | `GET /api/auth/knowledge-graph` | 树形前后置链 |
| 学习洞察 | Insight（LLM 生成） | `GET /api/auth/insight` | 文字评估报告 |

**ProfilePanel 交互**：默认不展示编辑表单，年级和薄弱知识点不是每次打开画像时看到的。Header 有轻量"编辑资料"按钮，点击后出现仅含年级的编辑区。取消不关闭弹窗，只退出编辑模式。薄弱点来自系统诊断，不要求用户手填。

## 关键表

| 表 | 内容 |
|----|------|
| `math_profiles` | user_id, 15 维分数, weak_points, latest_diagnostic_report, last_diagnosed_at |
| `knowledge_stages` | user_id, concept_name, stage (0-5), confidence |
| `pending_stage_updates` | 队列：delta_value / override_stage, source |
| `question_assessments` | 诊断快照：15 维分数 + overall_score + weak_concepts + summary |
| `chat_logs` | 对话日志：question, answer, sequence_id, is_analyzed |
| `user_knowledge_stats` | 行为统计：topic, consecutive_turns, total_asks |
