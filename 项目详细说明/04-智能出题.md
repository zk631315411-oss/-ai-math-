# 04 — 智能出题

智能出题系统**围绕当前教材页**生成递进式练习题，自动验算和质量门控制，支持错因分析驱动画像更新。

在“学数有道”的新定位下，智能出题不只是生成练习，而是认知诊断闭环的干预环节。系统应根据学生当前卡点、错因类型、知识点 stage 和提示依赖度，生成用于补救和验证的后续练习。

## 流程

```
POST /api/exercise/generate { textbook_id, page_number, user_id }
  │
  ├─ get_page_context(textbook_id, page_number) → chapter_name + sequence_id + 页面摘要
  ├─ get_user_avg_stage(user_id) → 全局平均认知阶段
  ├─ get_whitelist(textbook_id, sequence_id) → 动态白名单（不再硬编码）
  │
  ├─ build_exercise_prompt(章节名, 页码摘要, 白名单, stage) → LLM 出题 Prompt
  │
  ├─ LLM 流式输出 SSE:
  │   { stage: "generating", text: "正在生成题目..." } → 逐 token → { stage: "parsing", text: "正在解析题目..." }
  │
  ├─ parse_markdown_sections() → 按标题名解析（## 题目 / ## 答案 / ## 提示 / ## 验证 / ## computable）
  │   缺题目或缺答案 → 直接失败，不入库
  │
  ├─ SymPy 验算（如有 computable）:
  │   验算失败 → 不入库，返回错误提示
  │   验算通过 → save_exercise()
  │
  └─ SSE done: { exercise_id } → 前端拉取题目列表

POST /api/exercise/{id}/submit
  │
  ├─ LLM 同步批改: { is_correct, grading_feedback }
  ├─ save_exercise_attempt() → exercise_attempts（V2 分源评分的练习证据源）
  │
  └─ 错误（is_correct=False）→ BackgroundTasks（异步）:
       ├─ analyze_error(question, answer, student_answer, stage, weak_points)
       │   weak_points 来自 get_math_profile(user_id)（不再写死空数组）
       │   Prompt 注入 KG 规则案例块（error_analyzer._build_rule_cases_block）
       ├─ save_user_error_analysis() + update_exercise_attempt_error() → 只存 analysis
       └─ 不 update_stage：update_stage(delta=-1) 已无调用方，Stage 只由 V2 投影器按证据更新
```

## 质量门

| 检查点 | 失败处理 |
|--------|---------|
| 解析后缺题目或缺答案 | 不入库，SSE 返回 error |
| computable JSON 解析失败 | 不验算，仍可入库（认定为非计算题） |
| SymPy 验算失败 | 不入库，SSE 返回 error + 原因 |
| LLM 异常 | SSE 返回 error，前端显示失败面板 |

非计算题（无 computable 字段）可跳过验算直接入库。

## SSE 事件

| event | data | 说明 |
|-------|------|------|
| `stage` | `{stage: "generating" / "parsing" / "verifying", text}` | 阶段提示 |
| `content` | `{content: "..."}` | LLM 输出 token |
| `done` | `{done: true, exercise_id: "xxx"}` | 生成成功 |
| `error` | `{error: "..."}` | 生成失败 |

## 错因分析

[error_analyzer.py](../app/services/error_analyzer.py) 在后台异步运行（BackgroundTasks，不阻塞提交响应）：

```json
{
  "error_category": "concept_confusion",
  "error_subtype": "definition_misunderstanding",
  "specific_error": "混淆了行列式和矩阵的记号",
  "related_concept": "行列式展开定理",
  "remediation": "建议回顾行列式的定义：det(A) = Σ...",
  "dimension_delta": {...},
  "stage_delta": -1
}
```

- **KG 规则案例注入**：`_build_rule_cases_block()` 从题目/答案中猜测概念名，调 `kg_v44.get_rule_cases_for_node` 查询规则案例（条件-结论-适用对象），结构化注入错因 Prompt，让 LLM 判断学生是"条件理解错误 / 条件→结论映射错误 / 适用对象错误"，而不是自由文本猜测（error_analyzer.py L44、L102-110）。
- **不再直接更新 stage**：`stage_delta` 字段保留为分析建议，但 `update_stage(delta=-1)` 已无调用方；Stage 只由 V2 投影器按 `exercise_attempts` 证据确定性更新（见 [02-学生画像](02-学生画像.md)）。
- v2.4 修复：`weak_points` 从 `get_math_profile(user_id)` 获取真实数据，不再传空数组。

后续应将错因分析结果标准化为可统计标签（V2 已提供结构化信号类型，见下方表格与 `diagnostic_signals`）：

| 标签 | 示例 |
|----|------|
| 定义不清 | 不能准确复述线性无关定义 |
| 条件遗漏 | 证明中漏掉"任意系数均为 0" |
| 符号误读 | 混淆矩阵、向量组、系数 |
| 证明起点缺失 | 不知道先设线性组合等于 0 |
| 前置知识缺口 | 不熟悉齐次方程组解空间 |

这些标签可对接 V2 的结构化信号类型（`SIGNAL_TYPES` 六类：concept_confusion / prerequisite_gap / procedural_error / hint_dependency / practice_request / insufficient_evidence，见 [02-学生画像](02-学生画像.md)），作为人工标注标签体系的起点，并支撑诊断卡片和后续复盘任务。

## SymPy 验算

[sympy_sandbox.py](../app/services/sympy_sandbox.py) — 安全沙箱：

- 子进程隔离执行（`multiprocessing` spawn，跨进程只传纯 Python 类型；Linux 下额外设 512MB 内存上限）
- 操作白名单 + 尺寸限制（矩阵 ≤ 10 阶、方程 ≤ 5 元等）
- 禁止 eval/exec/import 等危险 token
- 10 秒超时（子进程未在 10s 内返回即 terminate，返回 "Timeout (10s)"）
- 支持类型：matrix_eigenvalues, matrix_determinant, matrix_inverse, matrix_rank, system_solve, polynomial_roots, polynomial_factor

## 练习端点与教材题池

[exercise.py](../app/routers/exercise.py) 提供 6 个端点：

| 端点 | 用途 |
|------|------|
| `POST /api/exercise/generate` | LLM 流式出题 + SymPy 验算（围绕当前教材页） |
| `GET /api/exercise/by-page` | 按当前页取教材练习题（无 LLM，`list_by_sequence_id` 按 sequence_id 过滤 `exercise_bank` 中 `source='textbook'` 的记录，秒出） |
| `GET /api/exercise/list` | 用户练习历史（含生成的 LLM 题与做过的教材题） |
| `POST /api/exercise/{id}/submit` | 提交答案 + LLM 批改 + 写 `exercise_attempts` |
| `POST /api/exercise/{id}/hint` | 请求三级渐进提示 |
| `POST /api/exercise/{id}/report-error` | 用户报告题目错误（`report_user_exercise_error`） |

教材原题库：`exercise_items`（不可变题目模板，source 默认 'textbook'，`kg_mapping_status` 校验）供 practice 模块读取。自适应练习（practice）系统共 6 端点（草稿创建/查询、会话开始、作答提交、三级提示、重新生成，见 [app/routers/practice.py](../app/routers/practice.py)，端点清单见 [00-总览](00-总览.md)，模块说明见 [app/services/practice/README.md](../app/services/practice/README.md)）：练习永远来自服务端构建的已审核教材题池，练习作答统一以 `exercise_attempts` 形式回流 V2 诊断。
