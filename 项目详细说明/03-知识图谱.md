# 03 — 知识图谱

基于丘维声《高等代数（上册）》等教材构建的 **Neo4j v4.4** 知识图谱，是系统的知识骨架。提供概念前后置关系、章节锚定、知识边界白名单，并驱动前端知识图谱可视化。

在"学数有道"的新定位下，知识图谱不能只作为 RAG 检索或白名单约束，而要服务认知诊断：将学生表现映射到具体知识点、前置知识缺口和后续学习路径。没有知识图谱，系统只能给出自然语言式评价；有知识图谱，诊断才能落到可追踪、可更新、可干预的知识状态。

## 数据模型（v4.4）

### 节点类型（9 种）

| 标签 | 含义 | 示例 |
|------|------|------|
| Concept | 概念节点（核心） | 行列式、矩阵的秩 |
| Theorem | 定理节点 | 线性方程组解的判定定理 |
| Method | 方法节点 | 高斯消元法 |
| Formula | 公式节点 | Cramer 法则公式 |
| ProblemClass | 题目类别节点（应用索引） | 矩阵乘法计算题 |
| RuleCase | 规则案例（条件-结论结构） | 无解判定 |
| ConditionExpression | 条件表达式 | r(A) < r(A\|b) |
| Outcome | 结论/状态 | 线性方程组无解 |
| KnowledgeGroup | 知识组（按小节/规则主题组织节点） | 第 3 章第 5 节知识组 |

### 关系类型（16 种，三层架构）

| 层 | 关系 | 方向 | 含义 |
|------|------|------|------|
| 核心层 | `SUPERIOR` / `EQUATIVE` / `PART_OF` / `HAS_PROPERTY` / `USES` / `GETS` / `DERIVES` / `REFERS_TO` | Concept/Theorem/Method/Formula/ProblemClass 之间 | 学习路径、概念依赖、方法推荐 |
| 规则层 | `HAS_RULE_CASE` / `APPLIES_TO` / `HAS_CONDITION` / `HAS_OUTCOME` | 定理/公式/方法 → RuleCase → ConditionExpression / Outcome | 条件推理、错因定位 |
| 知识组层 | `HAS_MEMBER` / `HAS_ANCHOR` | KnowledgeGroup → 节点 | 按小节或规则主题组织节点 |
| 派生层 | `PREREQUISITE_OF` / `HAS_POSSIBLE_STATE` | 概念间 | 可从核心图与规则层推导，当前未实现派生逻辑 |

### 规模

- **2980 节点 / 4396 边**，9 节点类型 / 16 边类型；
- 覆盖教材：高等代数上册（已部署）、高等代数下册（与上册合并部署）、高等数学上下册（结构化 MD 就绪）。

### Section 节点 ID

```
教材id:Cxx:Sxx[:Uxx]     例如 gaodai_shang:C03:S05:U01
  │       │   │   │
  │       │   │   └─ Unit（单元，可选）
  │       │   └───── Section（节）
  │       └─────────── Chapter（章）
  └───────────────────── 教材 id（gaodai_shang / gaodai_xia / gaoshu_shang / gaoshu_xia）
```

由 [app/textbooks.py](../app/textbooks.py) 的 `section_node_id(textbook_id, sequence_id)` 从 `sequence_id`（如 `V1-C01-S03-U01`）构造。该格式支持前缀匹配：查 `gaodai_shang:C03:S05` 能匹配该节下所有知识组成员节点。

## 查询入口（kg_v44.py）

[kg_v44.py](../app/db/kg_v44.py) 是 v4.4 KG 的统一查询层，核心函数：

| 函数 | 功能 |
|------|------|
| `find_node(name)` | 按概念名精确/模糊匹配节点（返回 source_code / evidence_span） |
| `nodes_for_section(section_node_id)` | 取知识组 HAS_MEMBER 挂载的小节核心概念（默认 limit=40） |
| `nodes_up_to_chapter(textbook_ids, chapter_num)` | 取某教材累计到指定章的所有节点（默认 limit=120） |
| `related_nodes(name)` | 返回（支撑邻接, 扩展邻接）二元组：USES/SUPERIOR/PART_OF 入向为支撑，GETS/DERIVES/HAS_PROPERTY 等出向为扩展 |
| `search_nodes_in_book(book_id, query)` | 按书名文本反查（含别名匹配，scope_rank 排序） |
| `relation_neighbors_for_nodes(node_ids, book_id)` | 多个种子节点的一跳关系邻接 |
| `rule_cases_for_nodes(node_ids, book_id)` | 按节点查规则案例（HAS_RULE_CASE → HAS_CONDITION / HAS_OUTCOME） |
| `get_rule_cases_for_node(concept_name)` | 按概念名查规则案例（先 find_node 再查） |
| `prerequisite_candidates_for_section(section_node_id)` | 前置候选：本节概念沿 SUPPORT_REL_TYPES 一跳邻接去重 |
| `nodes_by_ids_in_scope` / `one_hop_relations_in_book` | 练习 KG 映射硬边界校验（kg_validation） |

`_node_map` 统一把 source_code / evidence_span 从 Neo4j 读出并返回给所有查询函数，`find_node` / `nodes_for_section` / `related_nodes` 均返回这两个字段。

## 问答白名单

每次提问时，[whitelist_db.py](../app/db/whitelist_db.py) 查询 v4.4 KG 生成四字段白名单（`get_whitelist`）：

```
current_nodes = nodes_for_section(section_node_id(textbook_id, sequence_id), limit=60)
prior_nodes   = nodes_up_to_chapter(cumulative_textbook_ids(textbook_id), chapter_num, limit=120)

返回结构：
  macro   — "允许使用高等代数教材第1章到第N章已经出现的概念、定理、公式和方法。"（宏观指令）
  micro   — 当前节 + 前置概念名拼接（"、".join，微观名单）
  current — 当前节概念名列表
  prior   — 累计到当前章的前置概念名列表
```

粗细结合：宏观 = 累计到当前章放行（防止超纲），微观 = 当前节 + 紧邻前置具体名单。缓存：`lru_cache(maxsize=64)` 按 (textbook_id, sequence_id) 缓存；KG 查询失败回退到 `_fallback_whitelist`。

## 前置缺口检测

[prerequisite_checker.py](../app/services/prerequisite_checker.py) 查询 knowledge_stages + Neo4j：

```
1. section_node_id = section_node_id(textbook_id, sequence_id)   # 前缀 教材id:Cxx:Sxx[:Uxx]
2. candidate_names = prerequisite_candidates_for_section(section_node_id)
   → 本节核心概念沿 SUPPORT_REL_TYPES（SUPERIOR/PART_OF/USES/GETS/DERIVES/HAS_PROPERTY/EQUATIVE/REFERS_TO）一跳邻接
3. knowledge_stages：查询每个候选概念的 stage
4. 判断：stage IS NULL OR stage ≤ 2 → is_gap = true
5. 最多 8 个 gap 概念 → 生成提醒块注入 Prompt
```

KG 不可用时回退到 `related_nodes`（支撑/扩展邻接）兜底。`build_prereq_prompt_block` 与视觉 Prompt 共用。

## 规则案例层

v4.4 把数学中的条件判断结构化为专门的关系，而不是压成一条普通边。结构：

```text
定理/公式/方法
  --HAS_RULE_CASE--> 规则案例 RuleCase
  规则案例 --APPLIES_TO--> 适用对象
  规则案例 --HAS_CONDITION--> 条件表达式 ConditionExpression
  规则案例 --HAS_OUTCOME--> 结论/状态 Outcome
  条件表达式 --REFERS_TO--> 核心知识点
```

应用层消费：

- **QA grounding**：`grounding_service` 对种子节点调 `rule_cases_for_nodes`，按 scope/相关性排序后注入 `KGContext.rule_cases`，Prompt 用它组织严谨步骤（"先核验适用条件，再使用对应结论"）；
- **错因分析**：`error_analyzer._build_rule_cases_block` 调 `get_rule_cases_for_node`（limit=3），把规则案例结构化注入错因分析 Prompt，让 LLM 判断学生是"条件理解错误 / 条件→结论映射错误 / 适用对象错误"；
- **诊断卡片**：`GET /api/auth/diagnostic-cards` 对每个薄弱概念查 `get_rule_cases_for_node`，返回 `rule_cases` 数组供前端展示。

## 知识图谱 API

`GET /api/auth/knowledge-graph`（auth.py）— 从 `knowledge_stages` 取 stage ≤ 2 的薄弱概念（最多 5 个），对每个概念：

```
find_node(concept_name)            # 匹配 KG 节点（含别名纠偏 neo4j_name）
related_nodes(name, limit=5)       # 支撑邻接（前置）+ 扩展邻接（后置）
get_stages_batch(user_id, all_needs)  # 批量查每个节点的 stage
返回：{ name, stage, stage_label, prerequisites: [...], dependents: [...] }
```

返回每个薄弱概念的 stage + 前后置概念列表 + 各概念的 stage_label（未接触/入门/理解/应用/分析/综合/未知）。前端 [KnowledgeGraph.tsx](../frontend/src/components/KnowledgeGraph.tsx) 树形卡片展示：前置（黄）→ 薄弱概念（红/蓝框）→ 后置（灰/绿）。

## 构建管线

v4.4 知识图谱由**教材提取模块**下的 27 个编号脚本（00~09）多轮 LLM 流水线构建，路径：

- 流水线入口：[教材提取模块/高代提取/](../教材提取模块/高代提取/)（27 个编号脚本 + 运行包装脚本）
- 步骤说明文档：`教材提取模块/高代提取/v4.4_step说明.md`
- 数据文件在 `教材提取模块/中间产物`（`08_import_neo4j.py` 的 `FINAL_DIR = SCRIPT_DIR/"中间产物"/"step8_final_graph"`）；`高代提取/隐式边_runs` 和 `高代提取/归档` 也存放运行产物。Neo4j 导入由 `08_import_neo4j.py` 完成

```
00 准备配置 → 01 构建教材树 → 02 生成小节摘要
→ 03 显式节点提取（含示例帧）→ 04 显式边提取 + 规则案例提取与审计
→ 05 全局归一化与评审 → 06 分层候选构建
→ 07 AI 评审门禁（review items / ai review / 决策应用 / 冲突解决 / 报告）
→ 08 汇总成图 + 导入 Neo4j → 09 应用验证
```

注意：仓库根目录的 [pipeline/](../pipeline/) 是 **Legacy** 旧构建脚本（v4.2 时代），已不再维护，仅保留参考。
