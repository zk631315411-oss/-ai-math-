# 03 — 知识图谱

基于丘维声《高等代数（上册）》构建的 Neo4j 知识图谱，是系统的知识骨架。提供概念前后置关系、章节锚定、知识边界白名单，并驱动前端知识图谱可视化。

在“学数有道”的新定位下，知识图谱不能只作为 RAG 检索或白名单约束，而要服务认知诊断：将学生表现映射到具体知识点、前置知识缺口和后续学习路径。没有知识图谱，系统只能给出自然语言式评价；有知识图谱，诊断才能落到可追踪、可更新、可干预的知识状态。

## 数据模型

### 节点类型

| 标签 | 数量 | 含义 |
|------|:---:|------|
| Concept | ~4000 | 概念节点（核心） |
| Theorem | ~500 | 定理节点 |
| Formula | ~400 | 公式节点 |
| Problem | ~300 | 习题节点 |
| Section | ~35 | 章节节点（五级锚定） |

### 关系类型

| 关系 | 方向 | 含义 |
|------|------|------|
| `PREREQUISITE_OF` | Concept → Concept | 前置依赖（"行列式" → "特征值"） |
| `TEACH_IN` | Concept → Section | 概念属于哪个章节 |
| `DERIVED_FROM` | Theorem → Concept | 定理推导来源 |
| `USES_CONCEPT` | Problem/Theorem → Concept | 使用了哪个概念 |
| `HAS_ANSWER` | Problem → Formula | 习题参考答案 |

### Section 五级 ID

```
V1-C01-S03-U01-T00
 │   │    │   │   └─ Topic（主题）
 │   │    │   └───── Unit（单元）
 │   │    └─────────── Section（节）
 │   └──────────────── Chapter（章）
 └──────────────────── Volume（册 = 上册）
```

此设计支持 STARTS WITH 前缀匹配：查 `V1-C01-S03` 能匹配该节下所有单元和主题的概念。

## 构建管线

[pipeline/build_kg.py](../pipeline/build_kg.py) 离线运行，将教材 MD 解析为图谱：

```
1. 教材 MD 解析 → 提取知识节点（概念/定理/公式/习题）
2. 页码缝合 → PDF 书签 (PyMuPDF) + MD 标题序列 → 35 条章节记录
3. 节点入库 → MERGE 幂等写入，generate_unique_id() 去重
4. TEACH_IN 锚定 → 每个概念通过 sequence_id 挂到所属章节
5. PREREQUISITE_OF 推导 → 基于教材叙述顺序提取前置关系
```

## 系统集成点

### 认知诊断定位

| 图谱能力 | 对诊断的作用 |
|---|---|
| `TEACH_IN` 章节锚定 | 判断学生问题属于哪一节、哪些概念 |
| `PREREQUISITE_OF` 前置关系 | 判断卡点是否来自前置知识缺口 |
| `USES_CONCEPT` 题目-概念关系 | 将错题映射到相关知识点 |
| 前后置链查询 | 生成后续补救路径和复盘顺序 |
| 白名单约束 | 避免 AI 超出当前课程阶段讲解 |

### 问答白名单

每次提问时，[whitelist_db.py](../app/db/whitelist_db.py) 查询 Neo4j：

```cypher
MATCH (s:Section)<-[:TEACH_IN]-(c)
WHERE s.sequence_id STARTS WITH $seq_prefix  // 当前章级放行
RETURN c.id
+
MATCH (c:Concept)-[:PREREQUISITE_OF*1..2]->(prereq)
WHERE c.id IN $section_concepts  // 紧邻前置（Top 15）
RETURN prereq.id
```

粗细结合：宏观 = 当前章所有概念放行，微观 = Top 15 紧邻前置限制。

### 前置缺口检测

[prerequisite_checker.py](../app/services/prerequisite_checker.py) 查询 knowledge_stages + Neo4j：

```cypher
MATCH (n:Concept)-[:PREREQUISITE_OF]->(prereq:Concept)
WHERE n.name STARTS WITH $seq_prefix  // 当前节的概念
RETURN DISTINCT prereq.name
```

然后对每个前置概念查 `knowledge_stages`：stage IS NULL 或 stage ≤ 2 → is_gap = true。

### 诊断概念列表

[diagnostic.py](../app/db/diagnostic.py) 通过 `get_concepts_by_sequence_id(sequence_id)` 获取章节概念列表，注入诊断 Prompt 作为参考词汇表。LLM 从中选取概念输出 `concept_stages`。

### 知识图谱 API

`GET /api/auth/knowledge-graph` — 从 `knowledge_stages` 取 stage ≤ 2 的薄弱概念，查 Neo4j 前后置链：

```cypher
// 前置
MATCH (n:Concept {name: $name})-[:PREREQUISITE_OF]->(prereq:Concept)
RETURN DISTINCT prereq.name

// 后置
MATCH (n:Concept {name: $name})<-[:PREREQUISITE_OF]-(dep:Concept)
RETURN DISTINCT dep.name
```

返回每个薄弱概念的 stage + 前后置概念列表 + 各概念的 stage_label（入门/理解/应用/分析/综合/未知）。

## 前端可视化

[KnowledgeGraph.tsx](../frontend/src/components/KnowledgeGraph.tsx) — ProfilePanel 第 4 Tab。

树形卡片布局，纯 CSS 实现：

```
      前置1(🟡)    前置2(🟡)
           ↘         ↙
           薄弱概念(🔴蓝框)
           ↙         ↘
      后置1(⚪)    后置2(⚪)
```

颜色编码：红=入门(0-1)、黄=理解/应用(2-3)、绿=分析/综合(4-5)、灰=未知。箭头方向 = 依赖方向（前置→薄弱→后置）。蓝色边框突出当前薄弱概念。
