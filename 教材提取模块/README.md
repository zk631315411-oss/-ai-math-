# 教材提取模块

基于 Neo4j 知识图谱的教材知识提取与构建系统。

## 目录结构

```
教材提取模块/
├── README.md                   ← 本文件
├── 正式脚本/                    ← 生产级脚本，可反复运行
│   ├── build_kg.py             （旧 KG 构建脚本：LLM 全块抽取，GLM-4.5-Air）
│   └── 教材标题分级工具.py       （MinerU 原始 MD → 五级标题结构化 MD）
│
├── 测试调试/                    ← 临时测试、prompt 调试、单章试跑
│
├── 中间产物/                    ← 流水线中间输出
│   ├── *_clean.md              （正文清洗后）
│   ├── sections.jsonl          （结构解析：锚点索引）
│   ├── entities.jsonl          （实体抽取：规则 + LLM）
│   ├── nodes.jsonl             （实体归并：去重统一命名）
│   ├── candidate_pairs.jsonl   （关系候选召回）
│   └── edges.jsonl             （LLM 判关系输出）
│
├── 正式产物/                    ← 验证通过的最终产出 + 原始输入
│   ├── 原始PDF/                 （教材原始 PDF）
│   └── kg_v2_nodes.jsonl       （最终版节点，待入库）
│
├── 文档/                       ← 方案、交接、会议纪要
│   ├── KG_v2_构建计划.md         （KG v2 完整构建方案）
│   └── KG重建交接文档.md         （旧 KG 向新方案的交接说明）
│
└── .venv/                      ← Python 虚拟环境
```

## 分区约定

| 分区 | 放什么 | 不放什么 |
|------|--------|---------|
| `正式脚本/` | 可反复运行的构建脚本 | 一次性测试代码 |
| `测试调试/` | prompt 调试、单章试跑、格式验证 | 最终产物 |
| `中间产物/` | 各步骤中间输出（jsonl、md） | 最终入库文件 |
| `正式产物/` | 验证通过的完整图谱、原始 PDF | 中间草稿 |
| `文档/` | 方案、交接、会议纪要 | 代码 |

## 教材数据

权威教材数据统一存放在 `比赛相关文件与文件夹/揭榜挂帅/教材库/`，流水线格式：

```
原始 PDF → MinerU 解析 → _merged.md → _structured.md（五级标题）
```

各教材最完善的版本为对应目录下的 `_structured.md`：

| 教材 | 路径 |
|------|------|
| 高等代数上册 | `比赛相关文件与文件夹/揭榜挂帅/教材库/高等代数/高等代数上册_structured.md` |
| 高等代数下册 | `比赛相关文件与文件夹/揭榜挂帅/教材库/高等代数/高等代数下册_structured.md` |
| 高等数学上册 | `比赛相关文件与文件夹/揭榜挂帅/教材库/高等数学上册/高等数学上册_structured.md` |
| 高等数学下册 | `比赛相关文件与文件夹/揭榜挂帅/教材库/高等数学下册/高等数学下册_structured.md` |
| 离散数学（第六版） | `比赛相关文件与文件夹/揭榜挂帅/教材库/离散数学（第六版）/离散数学（第六版）_structured.md` |

## Neo4j 消费端

KG 由以下四个模块消费，Schema 设计需满足其字段需求：

| 模块 | 文件 | 功能 |
|------|------|------|
| 知识图谱可视化 | `app/routers/auth.py:352` | 薄弱概念 → 前后置依赖 |
| 前置知识检查 | `app/services/prerequisite_checker.py` | 学某节前查前置是否掌握 |
| 白名单生成 | `app/db/whitelist_db.py` | 当前章节允许使用的知识点范围 |
| 诊断溯源 | `app/db/diagnostic.py` | 章节概念列表 + 前置链 |
