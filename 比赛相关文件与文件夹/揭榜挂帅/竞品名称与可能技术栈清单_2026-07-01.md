## 2. 按技术路线归类

| 技术路线 | 对应作品 | 常见实现方式 |
|---|---|---|
| RAG + 垂类知识库 | 游学中国、数智琢材、智学数研、AI 数据标注岗位智能体 | 把教材、文献、标准、题库、岗位规范切片入库，用向量检索或混合检索增强大模型回答 |
| 知识图谱/能力图谱 + 大模型 | 数智琢材、琢玉、智学数研、EVOS | 用 Neo4j、NebulaGraph、RDF 或关系数据库建节点关系，再让大模型基于图谱定位知识、能力或岗位要求 |
| 多智能体协同 | 拟境求真、智域Agent、可能也包括智学数研 | 用教师 Agent、学生 Agent、评价 Agent、规划 Agent 等拆分任务，常见框架可能是 LangChain、AutoGen、CrewAI、Dify、Coze 或自研工作流 |
| 多模态识别 | 游学中国、智学数研 | OCR、图片理解、公式识别、语音识别、图文问答；数学项目尤其可能使用公式 OCR 和题目图像解析 |
| 实训/评价系统 | 琢玉、AI 数据标注岗位智能体、智域Agent | 任务发布、学生提交、Rubric 自动评分、教师复核、过程数据记录、技能等级报告 |
| 画像/诊断/推荐 | EVOS、琢玉、智学数研、可能也包括我们 | 采集学习、训练或成果数据，形成能力画像，再推荐课程、练习、岗位或学习路径 |

## 3. 对“学数有道”最相关的竞品

### 3.1 智学数研

这是当前最直接的同赛道竞品，因为它也在数学垂类大模型方向，而且题名覆盖“教学研全场景”和“多模态”。

它背后很可能会做：

- 数学教材/题库/论文 RAG；
- 拍照题目识别与公式识别；
- 数学问答与解题；
- 教师备课、出题、批改；
- 学情分析或教师端看板；
- 可能包装成“数学垂类大模型”或“数学智能体平台”。

我们需要重点观察它有没有真正做出：

- 多模态输入是否稳定；
- 数学推理是否可靠；
- 是否有真实学生或教师试用；
- 是否有可量化效果验证；
- 是否只是“功能全”，还是有一个特别扎实的闭环。

### 3.2 拟境求真

它不是数学竞品，但会在“AI 教育研究”和“多智能体”表达上显得高级。

它背后很可能会做：

- 多个 LLM Agent 模拟教师、学生、观察员；
- 课堂行为脚本或事件流；
- 教学策略仿真；
- 教育实证指标统计。

我们需要重点观察它的薄弱点：

- 模拟学生是否可信；
- 仿真数据是否有真实数据校准；
- 能否证明仿真结果对真实教学有指导意义。

### 3.3 EVOS

它和我们都可能涉及“画像”和“能力诊断”，但它更偏宏观人才能力。

它背后很可能会做：

- 学生能力图谱；
- 课程、证书、岗位、成果数据融合；
- 能力差距分析；
- 成长路径推荐；
- 管理端可视化大屏。

我们需要重点观察它是否能落到具体学习过程。如果它只停留在宏观画像，我们可以用“具体知识点上的认知断点诊断”形成差异。

## 4. 暂时结论

从题名看，对手的技术包装集中在五类：

1. 垂类 RAG；
2. 知识图谱/能力图谱；
3. 多智能体；
4. 多模态识别；
5. 画像、评价与推荐。

这说明“知识图谱 + 大模型”本身已经不够稀缺。学数有道后续不能只强调自己有知识图谱、Graph-RAG、问答和 Demo，而要把技术栈落到一个更具体的核心能力上：在大学数学学习过程中，根据学生对话、错题、提示使用和练习表现，判断其知识掌握状态、认知断点和下一步干预方式。
